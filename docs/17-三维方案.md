# 三维方案

评估日期：2026-10-27。对象是 `VisionPlatform` 当前源码。约束与 [15-工具插件方案.md](../VisionPlatform/docs/15-工具插件方案.md) 相同：VS2022（v143）、C++17、Qt 5.15.2、Windows。平台只改一次。之后每加一种三维工具，只往 `plugins\tools`、`plugins\algos` 丢 DLL。

本文只落地「点云能在工具之间传递、能转着看、能拟合一个平面」。滤波、配准、匹配、网格和三维相机不在这一期。AI 推理见 [18-AI方案.md](18-AI方案.md)，两边的枚举各自追加，互不占用对方的整数值。

## 1. 结论

三维沿用工具壳加算法 DLL，不另起调度，也不把点云画进现有图像窗。

`HsCommData` 里点云和三维几何已经有了，单位是毫米，右手系，Y 向上。缺的是三处：

1. 工具端口只有图像、区域、轮廓、ROI、逻辑、二维位姿、数值。点云到不了下一工具。
2. `HsImageWindow` 是像素坐标的 `QGraphicsView`，不能绕着点云转。
3. 设计态刷新只找采集图和 `Graphic` 叠加。纯点云流程跑完，主视图是空的。

平台追加三种端口 `Cloud`、`Pose3`、`Shape3`，并在 `HsImageCtrl` 里加 `HsCloudWindow`。工具大类按功能追加四类：三维采集、点云预处理、测量、配准，不用一个叫 `ThreeD` 的维度分组。这一期只有测量下面有插件。样例是一个工具、一个算法：

| 工程 | 注册名 | 作用 |
|---|---|---|
| `plugins\tools\Plugin.Tool.Measure3D.FitPlane` | `measure3d.fit_plane` | 读 ASCII 点云或接收上游点云，写判断和显示用的输出 |
| `plugins\algos\Plugin.Alg.Pcl.Measure3D.FitPlane` | 同上，`algLib = pcl` | PCL 拟合平面，输出平面和内点 |

点云来源第一期是文件。没有上游 `Cloud` 时，工具壳读参数里的路径。不先做三维采集插件。

## 2. 现状

### 2.1 已经有的几何

定义在 `third_party\HsCommData\include\HsCommData`，实现已编进 `HsCommData.dll`。

| 类型 | 头文件 | 约定 |
|---|---|---|
| `Point3d` | `Geom3.h` | 右手系，毫米。X 向右，Y 向上，Z 朝向观察者。不是图像坐标，Y 不向下 |
| `Pose3` | `Geom3.h` | 平移加单位四元数。先旋转再平移。欧拉角不放在结构里，对接外部时用 `HsInterface3D.h` 的 `toPose` / `fromPose` |
| `Aabb3` | `Geom3.h` | 轴对齐包围盒。空盒是某一维 max 小于 min |
| `Cloud3` | `HsCloud.h` | `xyz` 必有。`normals`、`gray`、`rgb` 可空，非空必须与点数相同。`width`、`height` 都为 0 表示无序；都大于 0 且乘积等于点数表示有序。注释写明没有单独的深度图类型 |
| `Mesh3` | `HsMesh.h` | 三角网格。这一期不进端口 |
| `Contour3` | `HsContour3.h` | 三维折线。这一期不进端口 |
| `Plane3` | `Shape3.h` | 过 `origin`，`normal` 为单位法向 |
| `Box3` | `Shape3.h` | 中心位姿加三个半长 |
| `Sphere3`、`Cylinder3`、`Line3`、`Circle3` | `Shape3.h` | 球、圆柱、线段、三维圆 |

这些类型整份拷贝，不共享缓冲。和 `HsImage` 的像素 `vector` 同一做法。

### 2.2 工具链还是二维

| 位置 | 现在的行为 |
|---|---|
| `VisionCommon\common\PortTypes.h` 的 `PortData` | `Image`、`Region`、`Contour`、`Roi`、`Logic`、`Pose`、`Tuple`。`Pose` 对应 `Pose2` |
| `ToolIo` | 上面几类各一个数组。`appendByType` 按类型逐个分支转发，没有默认分支。新类型不写分支就丢 |
| `ToolOut::syncIo` | 只把图像、逻辑、二维位姿、`HsObject` 几何对齐到 `io`。不认识点云 |
| `AlgToolIn` / `AlgToolOut` | 图像、二维 ROI、`Pose2`、区域、轮廓。`runAlgToolBase` 填这些字段，调 `shot_init`、`execute`、`settle_result`，再 `syncIo` |
| `Job::inputIo` | 按连线调用 `appendByType`。类型分支补上之后，连线本身不用再写一套 |
| `ToolType` | 采集到标定。`toolTypeIsImageSource` 只有采集、预处理、标定。`toolTypeIsOverlaySource` 是定位、检测、结果处理 |
| `toolTypeTitle` | 不认识的类型落到「采集」。新大类必须自己写分支 |
| `HsImageWindow` | `QGraphicsView`。场景和像素 1:1。底图、结果叠加、ROI 都是 `Graphic` |
| `DesignWorkspace` 跑完流程 | 底图来自 `jobOut.source`，否则第一台采集工具的缓存图。叠加来自 `cachedOverlay`。没有图像就不调用 `applyFrame` |
| 运行工站 | `StationRuntimePanel` 最多 9 个 `HsImageWindow` |
| 调试 | `ToolDebugHost` 一个 `HsImageWindow` |

`HsObject::ObjectKind` 只有图像、区域、轮廓、多边形、圆、椭圆、矩形、线段。没有三维项。二维对象是像素，三维对象是毫米。放进同一个联合体后，跟随位姿和 `toGraphics` 都会拿错坐标系。三维不进 `HsObject`，也不进 `Graphic`。

## 3. 端口

枚举只追加在 `PortData::Tuple` 后面，已有整数值不变。旧方案没有这些口，打开时不用迁移。

| 值 | 键后缀 | 界面名 | 载体 |
|---|---|---|---|
| `Cloud` | `cloud` | 点云 | `PortCloud` |
| `Pose3` | `pose3` | 三维位姿 | `PortPose3` |
| `Shape3` | `shape3` | 三维形状 | `PortShape3` |

`portDataTitle`、`portDataSuffix`、`portDataFromSuffix` 三处一起补。缺任何一处，界面会把新口显示成「图像」，或从键解析不出类型，连线对不上。

### 3.1 PortCloud

```text
port      口名，空为缺省口
index     该口上的序号
cloud     Cloud3
native    NativeRef，同库指针，可空。跨库和界面只用 cloud
```

有序点云的深度就在 `cloud.xyz` 里，用 `width`、`height` 还原行列。不增加 `PortData::Depth`。一张高度图若只有 Z、没有 XY，由产生它的工具在读入时按像素当量和一个原点把 Z 展开成 `xyz`。展开规则写在那个工具的参数里，不写进 `Cloud3`。

### 3.2 PortPose3

```text
port      口名
index     序号
pose      Pose3
```

不复用 `PortPose`。现有位姿是平面上的 x、y、角度，`Job` 里还有 `inputPose` 专门填这个口。三维刚体若塞进同一口，下游找圆、卡尺会把四元数当成角度。

### 3.3 PortShape3

```text
port      口名
index     序号
kind      Shape3Kind
plane     kind 为 Plane 时有效
box       Box
sphere    Sphere
cylinder  Cylinder
line      Line
circle    Circle
```

`Shape3Kind` 一次列全：`Plane`、`Box`、`Sphere`、`Cylinder`、`Line`、`Circle`。存盘用这个整数。这一期只有拟合平面会写出 `Plane`。其余种类留在类型里，不出现在样例工具的端口说明里，避免下次加球、圆柱时再挪枚举。

空形状的判断沿用各结构自己的 `isEmpty`。无限圆柱没有有限包围盒，点云窗这一期不画它。

### 3.4 ToolIo 与算法入出参

`ToolIo` 增加三个数组：`clouds`、`poses3`、`shapes3`。`appendByType` 为三种 `PortData` 各加一个分支，规则与现有点云以外的口相同：按口名过滤，`index < 0` 表示整口，写到目标口名上。

`AlgToolIn` 增加 `clouds`、`poses3`。`AlgToolOut` 增加 `clouds`、`poses3`、`shapes3`。`runAlgToolBase` 在调用算法前把 `ToolIn.inputIo` 里的这三个数组抄进 `AlgToolIn`，返回后抄回 `ToolOut.io`。这一步必须写死。现在的 `syncIo` 只对齐图像和 `HsObject`，不抄点云；算法就算填了 `AlgToolOut`，流程也连不出去。

`toGraphics()` 仍然只服务图像窗。点云窗直接读 `ToolIo` 的三个新数组。

连线规则不变：`portsTypeMatch` 要求数据类型相同。点云只能接点云。

## 4. 工具大类

现有大类按功能分：采集、预处理、定位、检测、逻辑、通信、结果处理、标定。`ThreeD` 按维度起名，和这套对不上。只加这一个类也不够：读点云、滤波、拟合、配准的默认端口和该不该进结果矩阵并不相同，塞进一个分组后，工具箱里点云工具会堆成一列，默认端口表只能做成四类的并集。

也不能把它们放回现有类。这些类已经绑了图像行为：

| 现有类 | 绑死的行为 |
|---|---|
| `Acquire` | `Job` 在执行前填相机设备、采图路径和帧号。`StationLoop` 用「有没有采集」决定工站是否连续跑 |
| `Preprocess`、`Calib` | `toolTypeIsImageSource` 为真，设计态拿它的输出当底图。`JobCfg` 自动连线会连 `Image` |
| `Locate` | 自动连线连的是二维 `Pose` |
| `Detect`、`RstProcess` | 自动连线连 `Region`，并进入图像叠加 |

点云工具放进去之后，要么被当成一张图去连线，要么被当成相机去调度。

在 `Calib` 后按下面的顺序追加四个功能类。整数只追加、不插入，和 AI 方案的 `Infer` 错开：这四个在前，`Infer` 在后。

| 枚举 | 界面名 | 做什么 | 默认端口 | 底图 | 图像叠加 | OK/NG | 这一期 |
|---|---|---|---|---|---|---|---|
| `Acquire3D` | 三维采集 | 文件或传感器把三维数据送进流程 | 出 `Cloud`、`Pose3`、`Shape3` | 否 | 否 | 否 | 不建插件。拟合平面自己读文件 |
| `Prepare3D` | 点云预处理 | 滤波、降采样、法向，点云进、点云出 | 入 `Cloud`，出 `Cloud` | 否 | 否 | 否 | 不建插件 |
| `Measure3D` | 测量 | 拟合、高度、平面度、距离 | 入 `Cloud`，出 `Shape3`、`Cloud`、`Tuple`、`Logic` | 否 | 否 | 是 | 拟合平面 |
| `Align3D` | 配准 | 点云或曲面得到刚体位姿 | 入 `Cloud`，出 `Pose3`、`Tuple`、`Logic` | 否 | 否 | 是 | 不建插件 |

界面名用三维采集、点云预处理、测量、配准。枚举用 `Acquire3D`、`Prepare3D`、`Measure3D`、`Align3D`。`Acquire3D` 与图像采集 `Acquire` 并列，界面名写成「三维采集」，避免工具箱里两个分组都叫「采集」。`Prepare3D` 不叫 `Preprocess`，那个名字已经被图像预处理占用。

`Acquire3D` 的默认端口是三类输出：点云、三维位姿、三维形状。具体工具只声明自己真有的口。读 PLY 的工具只出 `Cloud`。传感器若一帧里同时有位姿或几何，再声明 `Pose3`、`Shape3`。网格仍不在端口里。这一类不出图像，不参与 OK/NG。

具体工具的 `ports()` 可以比默认表少。拟合平面属于 `Measure3D`，不出 `Pose3`。

`toolTypeTitle` 四类各自返回上表的界面名，不能落到现在的 default（default 会显示成「采集」）。

`toolTypeDisplayAt` 这一期只把 `Measure3D` 加进展示顺序。工具箱按这个顺序建分组，空分组也会出现父节点。`Acquire3D`、`Prepare3D`、`Align3D` 还没有插件，先不放进展示顺序，枚举值仍然占上，避免以后往中间插值把已存盘的工具类型挤开。有插件的那天再放进展示顺序。

`JobCfg` 里按类型自动补图像、二维位姿、区域的逻辑，不要把这四类算进去。点云、三维形状、三维位姿只按用户拉的连线走，`portsTypeMatch` 认数据类型。

`Job` 里给 `Acquire` 填相机路径和帧号的分支不要扩到 `Acquire3D`。三维采集以后自己读参数里的文件或设备。`StationLoop` 用「有没有图像采集」决定连续跑时，也不要把 `Acquire3D` 算进去。

`ToolCaps.usesRoi` 对拟合平面为 false。搜索区见第 6.7 节。

## 5. 样例：拟合平面

### 5.1 工具壳

目录 `plugins\tools\Plugin.Tool.Measure3D.FitPlane`。只链接 `VisionToolBase`、`VisionAlgToolBase`、`HsCommData`。不链接 Qt，不链接 PCL，不链接 Halcon。

| 项 | 值 |
|---|---|
| `toolName` | `measure3d.fit_plane` |
| 大类 | `Measure3D` |
| 显示名 | 拟合平面 |
| 版本 | `1.0.0.0` |
| `usesRoi` | false |

端口：

| 方向 | 类型 | 口名 | 内容 |
|---|---|---|---|
| 入 | `Cloud` | 空 | 上游点云。空则读文件 |
| 出 | `Shape3` | 空 | 一个 `Plane3` |
| 出 | `Cloud` | `inlier` | 内点。点云窗用另一种颜色画 |
| 出 | `Tuple` | 空 | 下面这组测值 |
| 出 | `Logic` | 空 | 拟合成功且均方根在判断限内为 OK |

测值键固定，判断参数的 `name` 用同一套键，结果矩阵才能对上：

| 键 | 含义 | 单位 |
|---|---|---|
| `nx` `ny` `nz` | 单位法向 | 无 |
| `ox` `oy` `oz` | 平面上一点，取内点质心；没有内点时取参与拟合的质心 | mm |
| `rms` | 点到平面距离的均方根 | mm |
| `inliers` | 内点数 | 个 |
| `points` | 参与拟合的点数 | 个 |

参数页由 `paramFields()` 生成，不写专用 Qt 页。

| 块 | 键 | 缺省 | 含义 |
|---|---|---|---|
| run | `file` | 空 | 无上游点云时的路径。相对路径相对 `solutionDir` |
| run | `distance` | 0.5 | 内点距离阈值，毫米。小于 0 视为 0 |
| judge | `rms` | 0 到 1 | 参与总判定 |

`execute` 顺序：

1. 取输入点云。`inputIo.clouds` 非空用第一幅；空则按 `file` 读取。两条都空：`error = true`，说明「没有点云」。
2. 路径打不开，或扩展名不是 `.ply` / `.pcd`：`error = true`，说明里带上路径。
3. 格式不对：`error = true`，说明是缺 `element vertex`、缺 `x y z`，还是出现了二进制头 `format binary`。
4. 调用 `runAlgToolBase(toolName(), in, false)`。`passImage` 为 false，这个工具没有输出图。
5. 若返回码是未登记算法，工具壳把说明改成「未登记测量算法」。`runAlgToolBase` 里的原句是「未登记图像算法」，二维工具继续用原句，不改公共字符串。
6. 算法把平面和内点放进 `AlgToolOut` 后，由第 3.4 节的抄回逻辑进入 `ToolOut.io`。工具壳不再拆一遍。
7. 均方根超出 `judge` 里名为 `rms` 的上下限：`ok = false`，`errCode = 0`，`error = false`。这是 NG，流程按现有失败策略处理。点数不够、点共线、文件错误才是 `error`。

文件读取放在工具壳，算法只看见 `Cloud3`。这样换 Halcon 实现时不用再解析 PLY。

支持的文件：

| 格式 | 接受 | 拒绝 |
|---|---|---|
| ASCII PLY | `format ascii`，`element vertex` 后每个顶点至少三个浮点数，按 x y z 取 | `format binary_little_endian`、`binary_big_endian`、只有面没有顶点 |
| ASCII PCD | `FIELDS` 含 x y z，`DATA ascii` | `DATA binary`、`binary_compressed` |
| 其他扩展名 | 不读 | 说明写「只接受 ply 和 pcd」 |

法向、颜色、强度这一期读到就丢，不写入 `normals` / `rgb`。点数为 0 的合法文件当作「没有点云」。坐标已经是毫米。文件若是米，由使用者在外部换算，工具不猜单位。

读入的点云不从输出缺省口再送出去。输出点云口只有 `inlier`。点云窗要同时看到原始点和内点：原始点来自本工具的输入缓存，内点来自输出口。调试宿主在跑完后把这两份都交给窗口。流程下游若要原始点云，从更上游的工具连，不从拟合平面的缺省口连。

### 5.2 算法库

三维算法和二维同一套登记：一个实现一个 DLL，`algLib()` 决定进哪个库。二维是先有 Halcon 插件，华睿只留在 `AlgLibKind` 里，没有对应 DLL。三维照这个做。

`AlgLibCv` 后面追加两个值：

| 枚举 | 登记名 | 界面短标题 | 这一期 |
|---|---|---|---|
| `AlgLibPcl` | `pcl` | PCL | 有插件。拟合平面以及以后本机先写的三维算法都挂在这 |
| `AlgLibOpen3d` | `open3d` | Open3D | 只占枚举。不建工程，不放空 DLL |

`algLibKindTitle`、`algLibKindRegName`、`algLibKindFromRegName` 一起补。版本对话框的算法库列加上 PCL 和 Open3D。没有 Open3D DLL 时该列是否，和现在的华睿一样。工具参数里的库下拉只列出这个 `toolName` 已经登记的库，所以拟合平面的下拉里只有 PCL。

拟合平面的缺省 `algLib` 是 `pcl`。以后某个工具补了 Open3D 实现，同一 `toolName` 再挂一个 DLL，用户才能选到 Open3D。`getPreferred` 仍先用工具参数里指定的库。

预编译包放在 `third_party\PCL`，只提供 x64。算法 DLL 按自己用到的模块链接，拟合平面用 `common`、`sample_consensus`、`segmentation`。工具壳不链接 PCL，点云窗也不链接 PCL。界面继续只认 `Cloud3`，不用 PCL 的可视化窗口。

### 5.3 拟合平面的 PCL 实现

目录 `plugins\algos\Plugin.Alg.Pcl.Measure3D.FitPlane`。`algLib()` 返回 `AlgLibPcl`。

`execute` 开始把 `Cloud3` 的 `xyz` 抄进 `pcl::PointCloud<pcl::PointXYZ>`。法向和颜色不参与拟合。`NativeRef` 这一期不读，跨库只走 `Cloud3`。

拟合用 `pcl::SACSegmentation`，模型 `SACMODEL_PLANE`，方法 `SAC_RANSAC`。距离阈值用运行参数 `distance`，单位毫米。迭代次数固定 1000，随机种子固定，同一片点云两次运行得到同一组系数。

1. `clouds` 为空或第一幅 `isEmpty`：失败，说明「点云为空」。
2. 点数少于 3：失败，说明点数。
3. PCL 找不到平面，或内点少于 3：失败，说明「无法拟合平面」。
4. 系数是 `ax+by+cz+d=0`。法向取 `(a,b,c)` 并归一化。z 分量为负则整体取反，避免两次运行翻面；z 接近 0 时看 y，y 也接近 0 时看 x。
5. `origin` 取内点质心在平面上的投影。
6. PCL 给出的内点下标写回 `Cloud3`，`width = height = 0`，口名 `inlier`。
7. 均方根用内点到平面的距离。`points` 是输入点数，`inliers` 是内点数。
8. 读 `judge` 中 `name == "rms"` 且 `enable` 的项。超出上下限则 `ok = false`，`errCode` 保持 0。没有这条判断时，拟合成功即 `ok = true`。

`Plane3.normal` 写入前确认长度接近 1。`signedDistance` 在法向未归一化时会按法向长度缩放，点云窗和以后的测量都依赖它是单位向量。

## 6. 三维显示

### 6.1 现有图像窗为什么不够

`HsImageWindow` 的场景坐标就是像素。缩放只改视口。叠加是 `QGraphicsItem` 一类的二维图元，一条 `Graphic` 对应有限个圆、线段、文字。

点云是毫米坐标里的几万到几百万个点。用图元逐点去画，数量上去之后移动视图会卡。把点先投影成一张图再贴进图像窗，就失去了旋转。两种做法都留不住「拿着模型转」这件事。

| 做法 | 判断 |
|---|---|
| 在 `HsImageWindow` 里逐点做图元 | 坐标系是像素，图元数量扛不住点云 |
| 把点投影成图片再 `applyFrame` | 能看一张快照，不能转 |
| Qt3D、Qt Quick 3D | Qt 5.15 要另装模块，和现有 Widgets 画布是两套场景 |
| VTK 或 PCL 的可视化控件 | 库大，窗口生命周期绑在第三方控件上。平台现在的约定是界面只认 `HsCommData` |
| Halcon 三维窗口 | 显示绑到 Halcon 授权。算法库不出现在界面控件里 |
| 新建 `HsCloudWindow` | 采用 |

### 6.2 窗口放哪

类放在 `HsImageCtrl`，单独 `HsCloudWindow.h` / `HsCloudWindow.cpp`。基类 `QOpenGLWidget`。公开头只出现 `HsCommData` 和 Qt 的窗口类型，不出现 OpenGL 的缓冲对象。

`VisionUi`、`VisionToolUi` 已经链接图像控件，跟着能用。算法 DLL 不包含这个窗。窗不读 PLY，不拟合，不改 `Cloud3`。

### 6.3 对外接口

| 调用 | 作用 |
|---|---|
| `setCloud(const Cloud3&)` | 换底点云。空云清空画面，保留相机复位到单位盒 |
| `addCloud(const std::string& name, const Cloud3&, Rgb8 color)` | 额外一层，例如内点。同名替换 |
| `removeCloud(name)` | 去掉一层 |
| `setShapes(const std::vector<PortShape3>&)` | 形状叠加 |
| `setPoses(const std::vector<Pose3>&)` | 每个位姿画一个小坐标轴 |
| `setColorMode(mode)` | 底点云着色。见下 |
| `resetView()` | 相机正对包围盒 |
| `cloud()` | 当前底点云的只读访问，调试用 |

颜色模式：

| 模式 | 行为 |
|---|---|
| 按高度 | 用底点云包围盒的 Z 范围映射到蓝、青、绿、黄、红。Z 范围为 0 时整片用绿色 |
| 按灰度 | 用 `Cloud3::gray`。数组为空或长度不对时退回按高度 |
| 按颜色 | 用 `Cloud3::rgb`。同样不合法时退回按高度 |

额外层的颜色由 `addCloud` 指定，不跟底点云的模式走。拟合平面把内点加成绿色。

形状画法：

| 种类 | 画法 |
|---|---|
| 平面 | 与底点云包围盒相交，得到一个凸多边形，半透明填充，再沿法向画一条短线表示正面 |
| 盒子 | 12 条边的线框。半长有负值则不画 |
| 球 | 三个主圆的线框 |
| 有限圆柱 | 上下两个圆加四条母线 |
| 线段 | 一条线 |
| 三维圆 | 一个圆 |
| 无限圆柱、空形状 | 不画 |

位姿轴的长度取包围盒对角线的 8%。红 X、绿 Y、蓝 Z，与数据坐标系一致。

### 6.4 相机

相机对着包围盒中心。初始位置在中心的 +Z 一侧，距离使包围盒在竖直方向约占画面 80%，上方向是 +Y。这和 `Geom3.h` 里「Z 朝向观察者、Y 向上」一致。

| 操作 | 结果 |
|---|---|
| 左键拖动 | 绕中心旋转。方位角绕世界上 Y，仰角限制在接近 ±90° 以内，避免翻过顶之后上方向突然反转 |
| 滚轮 | 沿视线前后移动。近裁剪面跟着拉近，避免点云被裁掉 |
| 中键拖动 | 在视线的平面里平移中心 |
| 双击 | `resetView` |
| 右键 | 这一期不做菜单 |

运行态和设计态都只有这组浏览操作。没有绘制工具，没有 `beginDrawSession`。

### 6.5 点和拾取

底点云上传成一个顶点缓冲，点大小 2 像素，深度测试打开。底点云指针和点数都没变时不重新上传。只改相机或叠加时只重画。

绘制预算 150 万点，含额外层。超过则按固定步长抽点上传。步长对每一层单独算。`Cloud3` 本体不抽，测距和拟合仍用全部点。画面角落写两行字：总点数，以及这一帧实际画出的点数。

拾取只针对已经上传的点。鼠标附近 6 像素内取深度最近的一点，状态栏显示它的 x y z，单位毫米。没有命中就清空这行。拾取结果不写进 `ToolOut`，不产生端口。

有序点云这一期也按散点画。不在窗里重建网格。`width`、`height` 只留给以后的高度图 ROI 使用。

### 6.6 界面怎么切换

主视图位置改成叠放的两页，占现在 `HsImageWindow` 的那一块，不并排。

| 页面 | 内容 |
|---|---|
| 图像 | 现有 `HsImageWindow`。底图、`Graphic`、ROI 会话都留在这一页 |
| 点云 | `HsCloudWindow` |

选中工具或刚跑完的结果里有点云、三维形状或三维位姿时，切到点云页。只有图像时留在图像页。两样都有时停在用户上次点的那一页，第一次默认点云页，因为这一拍的新结果在点云上。

要改的调用点：

| 位置 | 现在 | 改成 |
|---|---|---|
| `DesignWorkspace` 跑完流程、刷新预览 | 没有底图就只尝试画 `Graphic` | 从该流程工具缓存里取最后一幅点云和全部 `shapes3`。有点云则切到点云页 |
| `ToolDebugHost` | 只创建图像窗 | 同样两页。单工具运行后，输入点云做底，输出口 `inlier` 做额外层，输出平面做形状 |
| `StationRuntimePanel` 的格子 | 固定 `HsImageWindow` | 格子绑定的工具输出若是点云，这一格换成 `HsCloudWindow`。其余格仍是图像窗 |
| `RecheckWorkspace` | 图像 | 这一期不改 |
| `DeviceMgrDlg` 预览 | 图像 | 这一期不改。三维相机预览随采集插件再做 |

运行九宫格不要整页换成点云。一个工站可以同时有二维相机和一条点云结果。

设计态在点云页时，ROI 绘制会话仍只作用于图像页。当前工具 `usesRoi` 为 true 且没有点云时，自动回到图像页，避免人在点云页里找不到矩形工具。

### 6.7 搜索区留到下一期

拟合平面不画搜索区，用整幅点云。

下一期需要搜索区时按点云是否有序分开，仍不在三维视口里拖橡皮筋：

| 点云 | 做法 |
|---|---|
| 有序 | 把 Z 编成一张伪彩 `HsImage`（`PixelByte` + `EncodeRgb`，无效点用固定灰色），用现有矩形 ROI 画在图像页。运行时按行列下标回到 `Cloud3::xyz`。伪彩只给界面，不新增端口 |
| 无序 | 工具参数里给一个轴对齐盒：最小角、最大角，各三个数，单位毫米。点在盒外则不参与。点云窗把这个盒当成 `Box3` 线框画出来 |

`HsImageWindow` 的底图编码注释是 8 位彩色或灰度。高度若直接送 `PixelReal32`，现有窗没有承诺能显示，所以伪彩要在界面侧先变成 8 位图。

## 7. 数据流

```text
上游 Cloud，或参数 file
        |
        v
measure3d.fit_plane             壳读文件、改写「未登记」说明
        |
        v
Algo.Pcl.FitPlane             RANSAC 平面，内点，rms
        |
        +-- io.shapes3        点云页画平面
        +-- io.clouds[inlier] 点云页绿色内点
        +-- io.tuples         结果表：法向、质心、rms、点数
        +-- io.logics         OK / NG
```

`Job::inputIo` 已经按连线调用 `appendByType`。`Cloud` 分支补上之后，上游点云能进拟合平面，不用在 `Job.cpp` 再写一个 `inputCloud`。图像那条专门路径（没有连线时回退到 `inputImage`）不复制给点云。点云没有「流程默认底图」。

大类和端口按这些工具预留，这一期不建工程。

| 注册名 | 大类 | 输入 | 输出 | 说明 |
|---|---|---|---|---|
| `acquire3d.load_cloud` | `Acquire3D` | 无 | `Cloud` | 把文件读取从拟合平面里拆出去。拆的时候拟合平面的 `file` 参数仍保留 |
| `prepare3d.downsample` | `Prepare3D` | `Cloud` | `Cloud` | 降采样。代表点云预处理这一类，具体算法以后再定 |

| `measure3d.fit_sphere` | `Measure3D` | `Cloud` | `Shape3` | 种类用已经列好的 `Sphere` |

## 9. 内存

`Cloud3` 拷贝路径：读文件一份，`ToolIn` 一份，`AlgToolIn` 一份，内点另算一份。200 万点只有 xyz 时约 48MB 一份，三份在一百多兆。样例文件控制在这个量级。

不在这一期给点云单独做共享缓冲。图像今天也是整份 `vector` 拷贝。以后若线扫点云把工站内存顶满，点云和图像一起改，不出现两套所有权。

抽点只发生在 `HsCloudWindow` 的显存缓冲里。

## 11. 验收

1. 工具箱出现「测量 / 拟合平面」，不出现名为「三维」的分组，也不出现还没有插件的「三维采集」「点云预处理」「配准」。去掉 `Algo.Pcl.FitPlane.dll` 后执行失败，说明是「未登记测量算法」。Open3D 没有 DLL 时，拟合平面的算法库里只有 PCL。已有找圆工具失败时说明仍是「未登记图像算法」。
2. 一份不少于 3000 点的 ASCII PLY 能跑通。结果表有 `nx ny nz`、`rms`、`inliers`。把 PLY 换成声明了 `format binary_little_endian` 的文件，失败说明里能看出是二进制。
3. 点云页可以旋转、缩放、平移、双击复位。平面多边形随数据移动。内点为绿色，其余点按高度着色。角落能看到总点数和画出的点数。
4. 把拟合平面的点云口连到另一个拟合平面的输入上时，连的是内点口才有数据。缺省形状口不能连到点云口。
5. `rms` 放进判断限之外时，逻辑口为 NG，`error` 为 false。点数少于 3 时 `error` 为 true。
6. 打开一份没有三维工具的旧方案，图像窗的底图和叠加与改端口之前一致。只有二维工具的流程不会自动切到点云页。
