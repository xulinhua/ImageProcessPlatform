# 配置加密方案

日期：2026-10-27。对象是 `VisionPlatform` 当前源码。对照导图条目「参数配置加密」。

本文只加密配置文件。代码混淆见 [代码混淆方案.md](代码混淆方案.md)。许可证文件、申请码和注册码见 [许可方案.md](许可方案.md)，不在这里重写。

## 1. 结论

新增动态库 `VisionCfgCrypt`。配置在内存里仍是现在的 JSON 对象。写成磁盘之前加密，读入之后解密。界面和工站不接触密文。

加密的是这四类文件：`*.vpsol`、`data\settings.json`、`data\users.json`、`data\composites\*.json`。同一把库内密钥，所以一份方案可以拷到另一台安装了本软件的电脑上打开。不绑硬件。

日志、`vision.db`、方案旁边 `.vpdata` 里的图像和模型不加密。模型由算法按路径直接打开，加密后 Halcon 读不到。

旧的明文 JSON 仍能打开。打开后的下一次保存写成密文。

## 2. 现状

| 文件 | 现在的内容 | 谁读写 |
|---|---|---|
| `*.vpsol` | 方案 JSON。工站、流程、工具参数、连线、运行界面布局 | `VisionCfgMgr` 的方案读写 |
| `data\settings.json` | 本机设置。主题、语言、倒计时这类字段会进这里 | `VisionCfgMgr::loadSettings` / `saveSettings` |
| `data\users.json` | 用户库。角色和口令哈希 | 用户库的加载和保存 |
| `data\composites\*.json` | 独立组合，一个文件一份 | `CompositeMgr` |
| `*.vpdata` | 工具目录。模板、图像等二进制 | 算法自己按路径读写 |
| `data\logs`、`data\vision.db` | 日志和数据库 | 不在配置读写这条路上 |

口令哈希不是配置加密。用户库文件今天仍是明文 JSON，打开就能看到用户名和哈希。

## 3. 模块和类

`VisionCfgCrypt` 不链接 Qt、Halcon。`VisionCfgMgr` 链接它。界面工程不链接它。

```text
CfgKey           不导出。库内这把配置密钥
CfgBlob          磁盘上的一头一尾：魔数、版本、随机数、密文、校验
CfgStore         按路径读、写。写之前加密，读之后得到 UTF-8 JSON 字节
```

| 类 | 职责 |
|---|---|
| `CfgKey` | 只在 cpp 里。配置密钥和许可密钥不是同一把，也不从硬件摘要推导 |
| `CfgBlob` | 把一段 JSON 字节收成密文，或把密文还原成 JSON 字节。校验失败就失败，不返回半截明文 |
| `CfgStore` | `read(path)`、`write(path, jsonBytes)`。调用方拿到的始终是 JSON 字节 |

`VisionCfgMgr` 和 `CompositeMgr` 仍负责把对象收成 JSON、把 JSON 收成对象。它们只在真正碰磁盘时调用 `CfgStore`。不在 `JsonValue` 里加密。

文件头是魔数 `VPC1` 加版本号。不是这个头、又不是以 `{` 或 `[` 开头的，视为损坏，走现在的损坏失败，不用空配置覆盖原文件。

以 `{` 或 `[` 开头的视为旧明文。`read` 原样返回这些字节，并告诉调用方「这是明文」。调用方照常解析。不在 `read` 里偷偷改掉原文件。下一次 `write` 才写成 `VPC1`。

每次 `write` 换一个随机数。同一份 JSON 两次落盘，密文不同。磁盘上不留 JSON 明文。

## 4. 哪些文件走它

| 路径 | 加密 |
|---|---|
| `*.vpsol` | 是。另存方案时写出的也是密文 |
| `data\settings.json` | 是 |
| `data\users.json` | 是 |
| `data\composites\*.json` | 是 |
| `*.vpdata` 下的图像、模型、区域文件 | 否 |
| `data\logs\**` | 否 |
| `data\vision.db` | 否 |
| `ProgramData\VisionPlatform\license\license.dat` | 否。那是许可证自己的格式 |

路径仍按现在的约定，相对 exe 的 `data`。不改到每个用户目录，避免管理员保存的方案标准用户看不到。

拷贝方案时，`*.vpsol` 和旁边的 `.vpdata` 一起拷。`.vpdata` 仍是原样二进制。对方电脑只要有本软件，就能解开 `*.vpsol`。

## 5. 失败

| 情况 | 行为 |
|---|---|
| 文件不存在 | 和现在一样，按「没有这份配置」 |
| 旧明文 JSON | 正常打开 |
| `VPC1` 校验失败、版本不认识 | 打开失败，保留原文件，界面用现在的损坏提示 |
| 目录不可写 | 保存失败，不写成半个文件 |

不因为解不开就生成一份新的空方案盖上去。

## 6. 不做什么

- 不加密代码，也不把函数放进虚拟机。那是 `VisionObfus`。
- 不加密许可证，不改申请码和注册码。
- 不把配置密钥绑到 CPU、BIOS 或磁盘上。绑定之后方案不能拷到同线的另一台电脑。
- 不加密 `.vpdata` 里给算法直接打开的文件。
- 不加密日志和 `vision.db`。
- 不在界面上做「输入密码才能打开方案」。密钥在库里，现场打开配置不另记一套口令。
- 本期不把「已经加密」说成别人拿不到参数。密钥在 `VisionCfgCrypt.dll` 里，能改这个 DLL 的人仍能解开。
