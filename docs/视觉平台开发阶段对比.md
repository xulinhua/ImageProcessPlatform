# 视觉平台开发阶段对比

对照来源：桌面 `视觉平台开发阶段.xmind`（根节点「视觉平台」）。对照对象：`VisionPlatform/VisionPlatform.sln` 当前源码。日期：2026-10-27。

本文只回答「导图里的阶段，解决方案里有没有」。实现质量、并发、口令和构建问题仍以 [`VisionPlatform项目评估.md`](VisionPlatform项目评估.md) 为准，这里不另立一套缺陷编号，也不改那份结论。

口径：只看源码和工程，没有重新编译，也没有跑界面。

- **已有**：导图这一条有可运行的实现。
- **部分**：有类型、界面或库，现场还不能按导图用。
- **未做**：没有对应实现。

## 1. 总览

导图四块的完成度不一样。

| 导图分支 | 结论 |
|---|---|
| 底层基础 | 方案、工站、流程、工具、手动试跑和工站循环已经能用。相机只有文件源，光源和运控没有运行时，通信能通一部分协议。 |
| 辅助功能 | 调试日志、操作记录、用户权限已经有。生产日志、数据库结果、标定和运控联动、方案升级降级还没有收口。 |
| 生产数据 | 运行界面有当次 OK/NG 和良率数字。批次、图表、按料追溯、结果还原、MES 都没有。复检是离线重跑文件夹，不是把历史记录导回来。 |
| 优化项 | 只有单进程 Qt 界面。加密、良率报警、高速模式、托盘、无窗口、分布式、脚本、3D、AI 都没有。 |

按导图叶子粗算：已有约 8 项，部分约 14 项，未做约 22 项。部分项不能当成阶段完成。

## 2. 底层基础

| 导图条目 | 状态 | 现在有什么 | 还差什么 |
|---|---|---|---|
| 数据结构、配置管理 | 已有 | `Solution` → 工站 → 流程 → 工具，方案文件 `*.vpsol`，读写在 `VisionCfgMgr` | 打开旧方案只记 `platformVersion`，不做兼容拦截。这是质量项，见已有评估 C1，不把「能存方案」记成未做 |

| 设备管理（相机、光源） | 部分 | 台账有相机 / 控制卡 / PLC。文件源采集可用 | 真相机后端直接返回「相机 SDK 未接入」（`CameraDeviceTool`）。光源没有独立设备和驱动，旧类型被并进控制卡台账 |
| 运控卡、IO 卡 | 未做 | 控制卡只出现在设备台账和工站芯片上 | 没有轴运动、IO 读写、运控 SDK |
| TCP、UDP、串口、Modbus | 部分 | `VisionComm` 有串口、TCP、UDP，以及 Modbus 主从（线圈、离散、保持寄存器、输入寄存器的读写接口） | 流程里的通信工具只做 `writeRegs`、`waitRegs`、`writePose`。UDP 明确不跑 Modbus。断线重连和现场功能码表没有收成可核对的清单 |
| PLC | 部分 | 可登记 PLC，并绑到通信通道；通信工具要求选 PLC 设备 | 没有按品牌 PLC 的协议栈，实际读写走上面的 Modbus 通道 |

## 6. 建议先补的阶段

下面按导图缺口排，不替代已有评估第 11 节的缺陷顺序。那一节优先收口的是失败策略、触发、连线真源、停止循环卡界面、口令。那些不补，底层「已有」的条目在现场仍会和配置不一致。

1. **采集和设备能上机**：相机 SDK、光源、运控或 IO。台账里现在能选出「真相机」和「控制卡」，运行对不上。
2. **生产数据能留下**：批次、OK/NG 落库、图像加测量值、按记录还原。复检导出放在还原之后，否则 CSV 只是本次重跑的表。
3. **方案版本能拦住**：不认识的 `platformVersion` 拒绝打开；工具参数版本和 DLL 版本不一致时标明，不要静默用默认值。
4. **运行形态**：高速模式、托盘或无窗口。分布式、脚本、3D、AI、加密狗、MES、CPK/GRR 可以排在能稳定出图、能追溯之后。

## 7. 本次没有核对的部分

- 各算法的精度和节拍。
- Modbus 在真实从站上的异常帧和断线行为。
- 标定残差门槛在真实九点数据上是否够用。
- 复检 JSON 报告能否被下一次启动读回来。源码里的保存是写出文件，没有看到按这份报告还原界面。
