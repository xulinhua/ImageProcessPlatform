# 本机进程通讯库方案

日期：2026-11-07。对象是给视觉平台和同机运控软件共用的独立库，下文称 `HsIpc`。本文定这个库的边界、传输、协议。三个内部进程的画面布局仍在 `VisionIpc`，映射和事件已经改由 `HsIpc` 创建。

视觉平台和运控软件在同一台电脑上交换 OK/NG、统计、图像和文件。走本机进程通讯，不走网卡。两边链接同一份 DLL，互不包含对方头文件。

## 1. 和现有模块的关系

`VisionIpc` 只服务本软件里的 `VisionApp`、`Vision.Station`、`Vision.Link`。共享内存名字仍是 `Global\Vision.Ipc`，槽里是命令、工站表和画面。这块内存和 `Vision.Command`、`Vision.FrameReady` 两个事件由 `HsIpc` 的区域接口创建，不再链接 `IpcBase`。布局仍由 `VisionIpc` 填写，不走运控那条报文通道。

`VisionPort` 是设备通道：串口、TCP、UDP、HTTP、WebSocket、Modbus。它没有本机进程通讯。`Vision.Link` 用它在两台电脑之间传画面，和本文不是一条链路。

| 模块 | 谁用 | 传什么 | 本次 |
|---|---|---|---|
| `VisionIpc` | 本软件三个进程 | 内部命令和画面槽 | 映射和事件改走 `HsIpc`，布局不变 |
| `VisionPort` | 设备和跨机器链路 | 字节流 | 不动 |
| `HsIpc` | 视觉平台和运控软件 | 信号、统计、图像、文件 | 新建 |

`HsIpc` 以后可以换掉 `VisionIpc`，但不是把调用从 `SharedFrames` 改成 `hs_ipc_send` 就结束。两边都是本机共享内存加命名事件，画面都是最新一帧、多槽避开正在读的那一槽。换的是三个进程之间的约定，不是再写一套映射。

现在对不上、替换前要补上的有四样：

| `VisionIpc` 现在有的 | `HsIpc` 这一版 | 替换时 |
|---|---|---|
| 头部命令：启动、停止、重载、订阅开关，服务堵在命令事件上 | 没有命令类型。Signal 是 OK/NG | 增加 Command 报文，或在落地第 2 步之前定好用 Signal 的名字表达这四条 |
| 编码直接写入槽，不再拷一份 | `send` 把字节交进去，库再写入槽 | 增加「取空槽指针、写完再发布」。编码器继续写进映射页 |
| 同一块内存分成本机槽和远端槽，下标固定 | 一个通道，用名字区分 | `Vision.Link` 把远端画面发成另一条 Image，名字带节点。不再保留两段固定下标 |
| 故障、角色、工站表放在头部 | 库不解释这些 | 仍留在视觉平台里，需要给别的进程看时填进 Signal 或 Stats |

换完之后 `IpcBase` 和 `VisionIpc` 可以删。`Global\Vision.Ipc` 这个名字不再使用，三个进程改开 `HsIpc` 的通道。运控继续用自己的通道名，不和这三个进程挤在同一条信号环里。

内部三进程仍用 `VisionIpc` 的头部和槽。运控走 `HsIpc` 自己的通道名，不和这三个进程挤在 `Global\Vision.Ipc` 里。

## 2. 工程

独立工程，输出一个 DLL 和一份 C 头文件。只依赖 Windows API。不依赖 Qt、Halcon、视觉平台、运控软件。

| 放进 DLL | 留在各自软件里 |
|---|---|
| 打开、关闭、收发 | 工站结果怎么填进报文 |
| 报文头和四种体 | 收到 OK/NG 之后怎么动作 |
| 共享内存、命名管道、消息队列、套接字 | 通道名字、槽大小 |
| 心跳、应答、序号 | 界面和运控逻辑 |

通道名由调用方传入，例如 `Hs.VisionMotion`，不写死在 DLL 里。谁先启动谁创建，后启动的打开已有对象。共享内存先放在 `Global\`，安全描述用空 DACL，这样会话 0 的服务和已登录用户能打开同一块。当前用户没有创建全局段的权限时，退回 `Local\`。两边要跨会话时，由有权限的一方先创建 `Global\` 对象。这是同机互信，不是安全边界。

对外是 C 接口，避免两边 Visual Studio 版本不同时 C++ 虚表对不上。C++ 工厂放在头文件里，只做 `create`，然后转调 C 接口。

```c
HsIpcSession* hs_ipc_open(const HsIpcConfig* cfg, char* err, int errBytes);
void          hs_ipc_close(HsIpcSession* s);
int           hs_ipc_send(HsIpcSession* s, const HsIpcMessage* msg);
int           hs_ipc_poll(HsIpcSession* s, HsIpcMessage* msg, int timeoutMs);
```

`HsIpcConfig` 至少包含：传输种类、通道短名、角色（创建方或打开方；实现上两边都可以先创建）、信号环容量、图像槽字节数、文件槽字节数。后三项只在共享内存上使用。

## 3. 工厂和传输

工厂按传输种类创建实现。调用方只组 `HsIpcMessage`，不写映射、管道或套接字。一条通道打开时选定一种传输，中途不换。四种都收发同一种报文，`hs_ipc_send` / `hs_ipc_poll` 不随传输变化。

视觉和同机运控只是其中一种场景。常用的四种都做进库，平级：

| 种类 | 行为 |
|---|---|
| 共享内存 + 命名事件 | 信号进环，图像和文件进槽。对端映射同一块页直接读。大块不进内核 |
| 命名管道 | 帧按顺序写进管道。图像和文件跟在帧头后面 |
| 消息队列 | 库内的命名队列，先进先出，每条留到被取走。不安装 MSMQ。和共享内存的槽不同：槽只留最新一份，队列不丢中间那条 |
| 套接字 | TCP 字节流，帧格式与管道相同。本机用 `127.0.0.1`，跨机器用对方地址。配置里带地址和端口 |

传图多、要少一次拷贝时用共享内存。要按顺序取走每一条 OK/NG 时用消息队列或管道。要跨机器时用套接字。同机只传信号时四种都可以。

信号量、命名事件只负责叫醒等待的一方，不是第五种数据传输。UDP 不保证帧送达，不作为这套报文的传输。窗口消息要有窗口，邮槽有长度上限且不保证送达，COM 把两边的类型绑在一起，这三种不进工厂。

`VisionPort` 仍管设备串口、Modbus 和现有的跨机器链路。`HsIpc` 的套接字只跑这份帧，不替代设备通道。

共享内存内部分两块，名字都挂在通道短名下面：

- 信号环。放 OK/NG、心跳、需要确认的短报文。满了返回失败，由发送方决定丢弃还是等待。不用覆盖写，避免丢拍。
- 图像槽和文件槽。只要最新一份。各三缓冲，写的人避开正在读的那一槽。统计也放最新一包，不进信号环。

命名事件两个：信号环有新报文时叫醒，槽发布时叫醒。自动复位。`global` 标志必须和这块共享内存一致。

命名管道、消息队列和套接字没有槽，也没有上面这两个事件。管道和套接字堵在读操作上，消息队列堵在队列上。这三种的图像和文件都跟在帧头后面。`dataBytes` 大于 1 MB 时拆片，每片仍是一帧，flags 的 bit0 表示后面还有片。统计和信号按到达顺序读。队列满了与信号环一样返回失败，不覆盖未取走的报文。

## 4. 协议

小端。定长头 32 字节。`version` 不认识则丢弃整帧。

| 偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | uint32 | magic | `HIPC`，字节为 `48 49 50 43` |
| 4 | uint16 | version | 从 1 开始 |
| 6 | uint16 | type | 见下表 |
| 8 | uint16 | flags | bit0 还有后续分片；bit1 体是槽引用而不是载荷 |
| 10 | uint16 | reserved | 0 |
| 12 | uint32 | seq | 该通道上的发送序号，从 1 递增 |
| 16 | uint64 | timeMs | 发送方毫秒时间 |
| 24 | uint32 | bodyBytes | 体长度。槽引用时体里是槽描述，不是像素 |
| 28 | uint32 | reserved2 | 0 |

`type`：

| 值 | 名字 | 含义 |
|---|---|---|
| 1 | Hello | 带上库版本和传输种类，对端不认识则拒绝 |
| 2 | Heartbeat | 周期发送。超时后对端把这条通道标成离线 |
| 3 | Signal | OK/NG 等短信号 |
| 4 | Stats | 一组文本键和数值，只保留最新一包 |
| 5 | Image | 一帧图像 |
| 6 | File | 一个文件 |
| 7 | Ack | 对指定 `seq` 的确认。图像默认不确认 |
| 8 | Bye | 主动关闭 |

字符串一律是 `uint16` 字节数加 UTF-8，没有结尾 0。名字由双方约定，DLL 不解释名字。

**Signal**

| 字段 | 类型 | 含义 |
|---|---|---|
| name | 字符串 | 工站或流程的键 |
| result | int32 | 0 未知，1 OK，2 NG |
| code | int32 | 双方约定的整数码，没有则为 0 |
| text | 字符串 | 短文本，可空 |

**Stats**

先写 `uint16` 项数。每一项是：键（字符串）、值类型（`uint8`，1 整数、2 浮点）、`int64` 或 `double`。

**Image**

| 字段 | 类型 | 含义 |
|---|---|---|
| name | 字符串 | 这一帧属于谁 |
| format | uint16 | 1 JPEG，2 原始像素 |
| width | uint32 | 宽 |
| height | uint32 | 高 |
| stride | uint32 | 行步长。JPEG 时为 0 |
| frameSeq | uint32 | 拍号 |
| dataBytes | uint32 | 像素或压缩后的字节数 |

共享内存且 flags 的 bit1 置位时，后面再跟 `uint32` 槽号。读方映射后把字节拷出，再释放槽。命名管道、消息队列和套接字上，像素紧跟在上述字段后面；`dataBytes` 大于 1 MB 时拆片，每片仍是一帧 Image，bit0 表示后面还有片。

**File**

| 字段 | 类型 | 含义 |
|---|---|---|
| name | 字符串 | 文件名，不含目录 |
| totalBytes | uint64 | 总长度 |
| crc32 | uint32 | 内容校验 |
| path | 字符串 | 双方都能读的绝对路径。为空表示内容在槽里或跟在帧后 |

优先传路径。对方读不了这块盘时，再占用一个文件槽，布局和图像槽相同。

**Ack**

`uint32` 被确认的 `seq`，`int32` 结果（0 成功，非 0 为双方约定的失败码）。

心跳超时由调用方配置，库只提供最后一次收到对端报文的时间。超时后调用方把该名字标成离线，不把最后一帧图像当成新结果。

## 5. 调用

视觉平台在一拍结束时组一条 Signal。需要计数时再发一条 Stats。要给运控看图时发布一帧 Image。运控侧 `poll`。两边都可以先启动。

视觉平台里的转换只有几行：检测结果填进 Signal 的 `name`、`result`、`code`。运控按 `name` 取出。这一层放在各自工程，不放进 DLL。

`Global\Vision.Ipc` 继续只给三个内部进程。运控通道用另一个短名。不要把运控报文写进现有画面槽。

## 6. 落地顺序

1. 建独立工程。先做共享内存、信号环、图像三槽、C 接口，加一个控制台对测程序，两边都链接这份 DLL。
2. 帧的编码和解码抽成与传输无关的代码。补上命名管道、消息队列和套接字。同一组对测四种传输都跑通。
3. 视觉平台加转换层，把工站 OK/NG、计数和 JPEG 送进这个 DLL。运控用同一 DLL 收。这一步不改 `VisionIpc`。

对测至少覆盖：先开任意一侧、信号环满、图像三槽同时读、心跳超时、管道和套接字分片、队列满、路径文件和槽文件。
