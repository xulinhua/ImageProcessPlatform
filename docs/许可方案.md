# 许可方案

日期：2026-10-27。对象是 `VisionPlatform` 当前单进程。对照导图条目「加密狗（启动、运行）」。软许可和硬件狗走同一个基类，本期只实现软许可。不改《VisionPlatform项目评估》和《视觉平台开发阶段对比》。参数配置加密、代码加壳各自另文。加壳见 [代码混淆方案.md](代码混淆方案.md)。

## 1. 结论

运行时只认基类 `LicenseSource`。软许可、以后的硬件狗都是它的子类。界面、启动和工站停止只调基类的 `open` / `poll`，不出现「现在是软的还是硬的」这种分支。

本期子类只有软许可。本机按硬件摘要生成申请码，厂家用申请码签发注册码，主程序验过注册码后加密写成许可证文件。授权分买断和到期日两种，格式相同。启动时授权无效，不进主窗。运行中授权被删、被改坏、验签失败或到期，都当成狗被拔掉：按设置里的倒计时继续跑，非模态窗口置顶提示。到时停止工站。是否退出程序由设置决定，默认不退出。

硬件狗本期不接 SDK，类先留空。软许可没有物理插拔，拔掉的定义就是上面这几种 `poll` 失败。狗接上之后，拔出 USB 走同一条 `poll` 失败。

## 2. 已定

| 项 | 决定 |
|---|---|
| 来源 | 基类两种实现。本期只构造软许可。设置里不出现「选狗」 |
| 启动失败 | 不进主窗，不倒计时。倒计时没走完就重启，新进程仍按启动失败，不继承剩余时间 |
| 运行中失效 | 文件或落盘授权被删、被改坏、验签失败、到期、时间被回拨，同一条倒计时 |
| 倒计时 | 本机设置可改。默认 10 分钟，允许 1～240 分钟。现在谁能开设置谁就能改。以后再收成最高权限，本期不做这道权限 |
| 到期日 | 含当天。次日 0 点起算失效。不精确到小时 |
| 倒计时中恢复有效 | 取消倒计时，关掉提示，正在跑的工站不停 |
| 到时 | 停止全部运行中的工站。默认不退出程序。设置为退出时，工站停完再退出 |
| 提示 | 非模态，窗口置顶，每秒刷新剩余时间 |
| 硬件绑定 | 申请码里带硬件摘要。注册码签的是这份摘要。摘要包含 CPU、BIOS/主板，以及 Windows 所在的那块内置盘。不含网卡，不含 USB 总线的盘 |
| 三份材料 | 申请码只在本机显示、发给厂家。注册码由厂家签发、用户粘贴。许可证文件是验过之后加密落盘的结果，运行时只读这一份 |
| 时间记录 | 加密后分三处存放。主程序不提供删除或复位。只有厂家工具能复位 |
| 加壳 | 本期不做。插件默认不加壳 |

| 位置 | 现在的行为 |

| `VisionApp\app\main.cpp` | 单实例互斥量之后初始化日志、加载插件、读用户和本机设置，再进主窗。没有许可检查 |

| 登录 | 人的角色，不是机器许可，也不是厂家工具的钥匙 |

## 4. 基类

`VisionLicense` 是解决方案里的一个 DLL。`VisionApp` 链接它。插件不链接它。

```text
LicenseSource
  open()     启动时建立许可。失败带原因
  poll()     运行中复查。从有效变成无效时，调用方开始倒计时。本函数不停止工站
  describe() 买断或到期日，给关于页和置顶提示用
  machineId() 本机硬件摘要，给启动失败窗口和厂家签发用

SoftLicense     本期实现
DongleLicense   本期空子类。open 返回「未接入」，运行时不会被构造
```

`main`、倒计时和停止工站只拿 `LicenseSource*`。换狗时替换构造的那一个子类，调用处不动。

`open` / `poll` 的原因分开记：没有授权、签名不对、硬件不符、产品不符、已过期、时间被回拨、记录被清掉。日志记原因和注册编号，不记私钥，不把申请码或注册码全文打进日志。

## 5. 软许可

### 5.1 申请码、注册码、许可证文件

三份材料各管一段，不能互相代替。

| 材料 | 谁产生 | 给谁 | 里面有什么 | 不负责 |
|---|---|---|---|---|
| 申请码 | 主程序，按第 5.2 节的硬件摘要现算 | 用户复制后交给厂家 | 产品名和硬件摘要 | 没有签名，没有买断或到期，不能当许可用 |
| 注册码 | 厂家工具，用私钥签 | 用户粘贴回主程序 | 产品名、编号、硬件摘要、买断或到期日、签名 | 不落盘。主程序验完就丢掉明文 |
| 许可证文件 | 主程序，注册码验过之后加密写成 | 本机下次 `open` / `poll` | 注册码的载荷和签名，密文保存 | 不由厂家工具写入。拷到别的电脑解不开 |

硬件摘要的采集规则见第 5.2 节。换 CPU、换主板，或更换 Windows 所在的内置盘之后，申请码会变，旧注册码和旧许可证文件都失效。只重装系统、插拔 U 盘，申请码不变。

本期不做在线激活。申请码和注册码都是离线字符串。公钥编进 `VisionLicense`。私钥只在厂家工具里，不进仓库，不进客户安装包。

#### 申请码

同一台电脑、同一套硬件，每次算出来的申请码相同。不放随机数。用户反复打开窗口，抄出去的还是同一串，厂家不用对着「哪一次生成的」核对。

载荷只有两段：产品名 `VisionPlatform`，以及第 5.2 节的硬件摘要。不含磁盘序列号原文，不含主板序列号原文，那些只进摘要。编码后加前缀 `VP-A1-`，每 5 个字符一组，方便口头或聊天工具抄写。

主程序在启动失败窗口和设置页「许可」上显示申请码，并提供复制。不提供「重新生成」。硬件没变时没有第二串可生成。

厂家工具只解码申请码，把产品名和摘要显示给人看。它不连接客户电脑。申请码验不出签名，被改过的申请码解出来的摘要是错的，据此签发的注册码回到真机器上对不上，主程序会拒绝。

#### 注册码

厂家在工具里选定买断或到期日，用私钥对下表签名。编码后加前缀 `VP-R1-`，同样每 5 个字符一组。前缀和申请码不同，粘贴到错误的输入框时直接拒绝。

| 字段 | 作用 |
|---|---|
| `product` | 固定 VisionPlatform。别的产品签发的码验过签也拒绝 |
| `licenseId` | 签发编号，只写日志 |
| `machine` | 从申请码解出的硬件摘要。必须与本机现算的摘要一致 |
| `kind` | `perpetual` 或 `until` |
| `until` | `until` 时的本地日期 `YYYY-MM-DD`，含当天。买断时忽略 |

用户在主程序里粘贴注册码，或导入一个只含这一串的文本文件。主程序用公钥验签，再对产品名、硬件摘要、种类和日期。任何一步失败都不写许可证文件，窗口留着原来的申请码。

验签用的摘要必须是当场按第 5.2 节重算的。不信任申请码窗口里缓存的旧字符串。管理员粘贴和非管理员粘贴，只要硬件没变，接受的是同一枚注册码。

#### 许可证文件

只有注册码验签成功才写入。路径固定为

`ProgramData\VisionPlatform\license\license.dat`

不放在 exe 旁边。安装目录在 `Program Files` 时，标准用户写不进去，管理员写进去之后标准用户又会变成「没有许可证」。也不放在当前用户目录下，否则管理员注册的许可，操作员登录看不见。安装程序创建这个目录，并给 Users 修改权限。目录建不出来或写不进去时，`open` 失败，原因单独为「无法保存许可证」，不改去别的路径。

文件布局：

| 部分 | 作用 |
|---|---|
| 魔数 `VPL1` 和版本号 | 不是这个头的文件视为被破坏 |
| 随机数 | 每次写入换一个，同样的注册码两次落盘密文不同 |
| 密文和校验标签 | 加密注册码的全部字段和签名 |

密钥由程序内的固定秘密和本机硬件摘要一起推导。摘要变了，旧文件解不开，按硬件不符拒绝。标签不对，按被破坏拒绝。解开之后再验一次签名，签名失败也按被破坏拒绝。磁盘上不留注册码明文。

`*.vpsol` 和 `settings.json` 不写申请码、注册码或许可证正文。运行中删除或改坏 `license.dat`，就是拔掉。三处时间记录不是许可证，删时间记录不会变成「没有注册」。

`open` 和 `poll` 只读这个文件，不再要求用户留下注册码。设置页显示从文件解开的种类、到期日和申请码。换新注册码并验过之后，覆盖这个文件，不保留上一份。

### 5.2 硬件摘要

摘要只表达这台电脑的 CPU、固件和系统所在的内置盘。采集函数只有一个，签发和校验都调它。管理员运行和标准用户运行必须得到同一个字符串。

不用 WMI。`Win32_BIOS`、`Win32_BaseBoard`、`Win32_DiskDrive` 在非管理员下经常是空串或占位符，提权后又变成真实序列号。同一次安装会算出两个摘要。也不打开 `\\.\PhysicalDriveN`，标准用户常常开不了这个设备，管理员可以。

无效字符串不参与摘要：空、只有空白、`None`、`Default string`、`To be filled by O.E.M.`、`System Serial Number`、全 0、全 `F` 的 UUID。比较前去掉首尾空白，连续空白收成一个，英文字母转成大写。

| 类 | 怎么读 | 写进摘要的内容 | 读不到时 |
|---|---|---|---|
| CPU | `CPUID` 指令 | 厂商字符串、family、model、stepping、品牌字符串 | 品牌和 family 都没有，则这一类缺席 |
| BIOS / 主板 | `GetSystemFirmwareTable` 读 SMBIOS 原始表 | 系统 UUID、系统序列号、主板厂商、主板产品名、主板序列号、BIOS 厂商、BIOS 版本。只写入上面规则判为有效的项 | 系统 UUID 和主板序列号都无效，则这一类缺席 |
| 磁盘 | 打开 Windows 目录所在卷，发 `IOCTL_STORAGE_QUERY_PROPERTY` | 仅当总线是 SATA、ATA、NVMe、SCSI、SAS、RAID 时，写入该盘序列号 | 见下方磁盘规则 |

磁盘只看 Windows 所在的那一块，不枚举机器上的其他盘。插上第二块硬盘或 U 盘，摘要不变。

总线是 USB、SD、虚拟盘或文件后端虚拟盘时，这一类整段缺席，不写入序列号。固态 U 盘在资源管理器里经常显示成本地磁盘，不能用「可移动 / 固定」来判断，只看总线。系统本身装在 USB 盘上时也不绑这块盘，CPU 和 BIOS 仍然绑定。

盘的序列号按上面的无效规则被丢掉时，不改用卷序列号。卷序列号一格式化就变，而且解决不了 U 盘被当成硬盘。

三类按 CPU、BIOS、磁盘的固定顺序拼接。某一类缺席就不留空段。CPU 品牌和系统 UUID 至少要有一个，否则 `machineId()` 失败，不能签发，也不能用这份空摘要去验授权。磁盘不是必须项。

不放进摘要的还有：网卡和 MAC、`MachineGuid`、内存、显卡、盘符、卷序列号、全部硬盘的清单。

### 5.3 时间记录

每次 `poll` 成功，把本机时间加密写入三处。三处算法不同，密钥都在 `VisionLicense` 内，不进设置，不进界面。

| 位置 | 作用 |
|---|---|
| 当前用户注册表 `Software\VisionPlatform\License` | 一处 |
| `ProgramData\VisionPlatform\license\tick.dat` | 一处 |
| 当前用户本地应用数据 `VisionPlatform\license\tick.dat` | 一处 |

复查时读三处里能解开的记录，取最晚的一次。系统时间早于这个时刻，视为回拨，`poll` 失败并开始倒计时。

三处里只删掉一部分时，其余仍在，回拨照样能看出来。三处都没有，而许可证文件还在：视为记录被清掉，`open` / `poll` 失败，原因单独列出。主程序不自动重建空记录，否则删光再改日期就能绕过。第一次成功 `open` 时三处本来就是空的，那时写入，不算被清掉。

主程序的设置页、关于页、置顶提示都不提供删除或复位。复位只在厂家工具里做。

## 6. 本机设置

`SettingsDlg` 增加一页「许可」，与现有四页并列。两项都进 `AppSettings`，随 `settings.json` 保存。读到越界值时收回默认，不让文件把倒计时写成 0 或写成几天。

| 项 | 默认 | 范围 |
|---|---|---|
| 许可失效后的倒计时（分钟） | 10 | 1～240 |
| 倒计时结束后退出程序 | 关 | 开或关 |

本期不看角色掩码。以后要收权限时，只给这一页的编辑权加上最高权限，不改倒计时的执行路径。关掉「退出程序」时，到点只停工站，主窗留着，人可以粘贴新注册码。

这一页显示申请码和复制按钮、注册码输入框，以及从许可证文件解开的种类和到期日。不编辑许可证文件正文。关于页同样只显示种类、到期日和申请码。

## 7. 运行

### 7.1 启动

`main` 在单实例互斥量拿到之后、加载插件之前构造 `SoftLicense` 并 `open()`。失败则对话框给出原因和申请码，然后返回。不加载插件，不读方案，不创建主窗，不开始倒计时。

### 7.2 倒计时

已经进主窗之后，界面侧每 30 秒 `poll()` 一次。仍有效则只更新时间记录。

第一次失败时按设置里的分钟数开始倒计时，弹出非模态窗口，加上置顶。窗口写明原因和剩余时间，并提供粘贴注册码。这期间各 `StationLoop` 继续 `tick`。窗口不用模态，避免把界面卡住后无法粘贴新码。

倒计时过程中 `poll` 恢复有效：取消倒计时，关掉窗口。

归零时，对每条正在跑的 `StationLoop` 调用 `stop()`。当前拍跑完，再 `runUnloadOnce`。不用 `haltAll`。设计态里已经开始的一次试跑让它跑完，到点之后不再启动运行循环。

「退出程序」为关：提示改为工站已停止，主窗还在。为开：工站全部 `stop()` 返回后再退出进程。退出前不再次 `poll`。

### 7.3 厂家工具

单独的 `Vision.LicenseAdmin.exe`，不放进客户桌面快捷方式，不进主程序菜单。它链接 `VisionLicense`，做两件事：解码申请码并签发注册码，以及在客户电脑上把三处时间记录复位成当前时间。签发不需要运行在客户电脑上，有申请码字符串即可。复位必须在那台电脑上做。这个工具不写 `license.dat`。

启动时核对厂家密钥。密钥不对就退出。不使用主程序里的操作员、工程师、管理员。主程序权限以后怎么收，都不给这三项角色复位时间记录的入口。

客户现场时间记录出了问题，只能在这台电脑上用厂家密钥打开这个工具做复位，然后主程序再启动。

## 8. 硬件狗以后怎么接

新增 SDK 时只填 `DongleLicense`。`open` 找狗，`poll` 看狗还在不在、狗内许可是否仍有效。狗内也要能表达买断和到期日。拔出、通信失败、狗内到期，都让 `poll` 失败。

倒计时、置顶提示、`StationLoop::stop()`、退出与否，仍用第 7 节。不在狗的代码里再写一套停止。

狗的时钟和本机时间记录互不替代。狗接上之后，回拨检查仍看第 5.3 节的三处记录；狗自己的到期由狗的 `poll` 报。本期不把 SDK 放进仓库。

## 9. 开发机

Release 不能跳过 `open()`。

Debug 允许编译进跳过开关，默认仍检查。开关用编译条件包住，不出现在 Release 里。现场包只发 Release。

开发机的买断授权同样绑定该机硬件摘要。不签发摘要为空的码。

## 10. 不做什么

- 本期不读 USB 狗，不把狗的 SDK 放进仓库。
- 不按插件、不按工站数量授权。
- 不在倒计时期间截断当前拍，也不在算子内部返回失败。
- 不用 `haltAll` 表示许可失效。
- 不上网校时，不做云授权。
- 不在主程序里删除或复位时间记录。
- 不加密 `*.vpsol`。那是参数配置加密。
- 本期不加壳。插件默认不加壳，见《代码混淆方案》。
- 不用 WMI 采集硬件，不把 USB 总线上的盘写进摘要。

## 11. 落地顺序

1. `VisionLicense`：基类、`SoftLicense`、申请码、注册码验签、许可证文件、买断和到期、硬件摘要、三处时间记录。`DongleLicense` 只有空实现，运行时不构造。
2. 厂家工具：解码申请码、签发注册码、复位时间记录。不进客户快捷方式，不写许可证文件。
3. `AppSettings` 与设置页「许可」两项。
4. `main` 接上启动失败对话框。
5. 运行中 `poll`、置顶非模态倒计时、到点 `StationLoop::stop()`，以及按设置退出。
6. 走一遍：买断、未到期、当天、次日、删许可证文件、改坏许可证文件、把许可证文件拷到另一台电脑、改系统日期、只删一处时间记录、三处都删、倒计时中粘贴新注册码、到点不退出、到点退出。申请码在硬件不变时重复打开仍相同；申请码粘进注册码输入框被拒绝。标准用户和管理员看到同一枚申请码，标准用户能把许可证写进 `ProgramData`。硬件摘要另测：插入固态 U 盘再拔掉，申请码不变；系统卷的总线是 USB 时，摘要里没有磁盘段。
