# 代码混淆方案

日期：2026-10-27。对象是 `VisionPlatform` 当前源码。对照导图条目「代码加密（混淆、加壳）」。

本文只处理代码。方案、设置、授权文件的加密是另一个模块，不在这里设计，也不由这里的类去读写。

本期先有模块和类。哪些函数改由它执行，以后再定。插件默认不加壳。不改全工程的编译器。

## 1. 结论

新增动态库 `VisionObfus`。它把一段函数变成自己的字节码，运行时由虚拟机解释执行。调用方二进制里不再有这段函数的原始跳转和算术指令。

本期只把库放进解决方案并编过。现有工程先不链接它，也不把现有函数搬进虚拟机。

加壳仍不做。壳是链接之后的外部步骤，不是这个库里的类。

## 2. 模块

| 工程 | 产物 | 本期 |
|---|---|---|
| `VisionPlatform\VisionObfus` | `VisionObfus.dll` | 放进解决方案，Debug 和 Release 都编 |
| 同目录下的内部工具 | `Vision.ObfusTool.exe` | 只在开发机把点名的函数打成字节码。不进客户安装包，不进开始菜单 |

`VisionObfus` 不链接 Qt、Halcon、OpenCV，也不链接 `VisionLicense`、`VisionCore`、配置读写相关的工程。它只依赖 C++ 标准库和 Windows API。

客户安装包里可以带上这个 DLL。本期没有调用方，不要求 `VisionApp` 加载它。

## 3. 类

```text
ObfusOp          一条字节码指令
ObfusProgram     一个函数的全部指令和常量
ObfusMachine     解释执行 ObfusProgram
ObfusValue       虚拟机上的一个整数或指针宽度的值
```

| 类 | 职责 |
|---|---|
| `ObfusOp` | 一条指令：操作码、目标寄存器、两个源。没有对应的「配置项」 |
| `ObfusProgram` | 保存一个函数的指令序列、常量池、寄存器数量、入口。构造参数是字节码，不是 C++ 源码文本 |
| `ObfusMachine` | 分配寄存器，从入口逐条执行。跳转只改虚拟机的指令指针，不生成原来的 `jcc` 指令 |
| `ObfusValue` | 寄存器里的值。整数按 64 位。指针只用于下面的外部调用 |

指令先具备这些操作码，够表达一段无 C++ 异常的整数逻辑：

| 操作码 | 作用 |
|---|---|
| `LoadImm` | 把常量池里的整数装入寄存器 |
| `Move` | 寄存器复制 |
| `Add` `Sub` `Xor` `And` `Shl` | 整数运算 |
| `Cmp` | 比较，结果写入寄存器，0 或 1 |
| `Jump` | 无条件跳到指令下标 |
| `JumpIf` | 寄存器非 0 才跳 |
| `CallOut` | 调用虚拟机之外的一个函数指针，参数和返回值走寄存器 |
| `Return` | 结束，返回值在指定寄存器 |

`ObfusMachine::run` 的参数是一个 `ObfusProgram` 和入口寄存器初值。返回 `ObfusValue`。程序空、操作码不认识、跳转越界时返回失败，不抛异常。

`CallOut` 的函数指针由调用方在 `run` 时传入一张表。字节码里只存表的下标，不存真实地址。表是空的时候，遇到 `CallOut` 就失败。

虚拟机不解释 C++ 异常，不跑 Qt 元对象，不生成 Halcon 算子调用。这些留在虚拟机外面，通过 `CallOut` 进入。外面的函数仍是普通编译结果。

## 4. 字节码从哪来

函数的源码仍用现在的编译器编译，用于对照结果。混淆后的形态是 `ObfusProgram` 的字节数组，由 `Vision.ObfusTool.exe` 生成。

工具本期只做一件往返：读一份手写的指令列表，写出 C++ 数组，库再 `run` 这段数组。不扫描现有业务 cpp，不改这些 cpp。

以后点名某个函数时，才把该函数的逻辑收成指令列表，调用处改成 `ObfusMachine::run`。没点名的函数保持现在的机器码。

## 5. 和另外两件事的分界

| 事项 | 归谁 | 本期 |
|---|---|---|
| 函数指令改成字节码再解释 | `VisionObfus` | 模块先有，不接入业务 |
| 方案、本机设置、用户库、组合文件加密 | [配置加密方案.md](配置加密方案.md) | 本文不定义类，不读写这些文件 |
| 给 exe 或 dll 加壳 | 链接之后的外部工具 | 不做 |

插件 `Plugin.*.dll`、Qt 的 `qwindows.dll`、Halcon、OpenCV 默认不加壳。`PluginHost` 仍按现有方式 `LoadLibrary`，导出 `VisionPlugin_apiVersion` 和 `VisionPlugin_register` 保持明文。

全工程换带混淆的编译器不做。Halcon 的 C++ 异常和 Qt 元对象依赖现在的指令形态。

Release 安装包不带 PDB。这是发布方式，不是代码混淆。

## 6. 不做什么

- 本期不把现有函数改成 `ObfusMachine::run`。
- 不加密 `*.vpsol`、`settings.json`、许可证文件，也不提供密封字符串的类。
- 不把界面文案、日志格式当成混淆对象。
- 不在虚拟机里实现 C++ 异常和 Qt 信号。
- 本期不给任何文件加壳，包括 `VisionObfus.dll`。
- 不把「库已经编过」说成业务代码已经被混淆。
