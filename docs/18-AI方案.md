# AI 推理方案

评估日期：2026-10-27。对象是 `VisionPlatform` 当前源码。约束与 [15-工具插件方案.md](../VisionPlatform/docs/15-工具插件方案.md) 相同：VS2022（v143）、C++17、Qt 5.15.2、Windows。平台只改一次。之后每加一种推理工具，只往 `plugins\tools`、`plugins\algos` 丢 DLL。

本文里的 AI 指产线上的模型推理。训练、标注、模型转换工具不进平台。三维点云见 [17-三维方案.md](17-三维方案.md)。三个工具都只吃图像，不使用点云端口。

## 1. 结论

推理沿用工具壳加算法 DLL。分类、目标检测、语义分割都要有，各是一个工具、一个 ONNX 算法 DLL。输入输出用现有端口：图像进；分类出数值和逻辑；检测出轴对齐矩形；分割出行程区域。平台不为这三件事新增 `PortData`。

真正缺的是运行时，加上图上的类别名。框和区域能经现有 `HsObject` 画出来。`cachedOverlay` 里没有文字，类别名现在画不回流程图像上。

| 缺口 | 现在 | 这一期 |
|---|---|---|
| 算法库 | `halcon`、`hik`、`hray`、`opencv` | 追加 `onnx` |
| 谁在跑算法 | `runAlgToolBase` 拿注册表里的原型直接 `execute`，不 `clone` | 保持这个方式。会话放在公共动态库 `VisionOnnxCom.dll`，按模型路径取 |
| `loadLearn` | 只有空实现，全工程没有调用点 | 三个工具都不依赖平台去调它。第一次 `shot_init` 时按 `toolDataDir` 懒加载 |
| 模型放哪 | 方案 JSON 不适合塞权重 | 文件放在该工具的 `toolDataDir`，方案里只留文件名 |
| 框和区域 | `Roi`、`Region` 已能叠加 | 检测、分割直接用 |
| 类别名 | 流程缓存的叠加只有 `HsObject`，`objectsToGraphics` 只产生几何 | 增加一列文字锚点，界面在几何之上补 `KindText` |

三个工具：

| 工具 DLL | 算法 DLL | 注册名 | 作用 |
|---|---|---|---|
| `Plugin.Tool.Infer.Classify` | `Plugin.Alg.Onnx.Infer.Classify` | `infer.classify` | 整图一个类别和分数 |
| `Plugin.Tool.Infer.Detect` | `Plugin.Alg.Onnx.Infer.Detect` | `infer.detect` | 多个框，带类别和分数，类内 NMS |
| `Plugin.Tool.Infer.Segment` | `Plugin.Alg.Onnx.Infer.Segment` | `infer.segment` | 每个前景类一块区域 |

同一 `toolName` 以后可以再挂 Halcon 实现。调度仍走 `getPreferred`。这一期不放海康、华睿、TensorRT 的推理 DLL。实例分割（每个目标一块掩膜）不是 `infer.segment`，见第 12 节。

## 2. 现状里和推理有关的部分

### 2.1 端口够用

`PortData` 已有 `Image`、`Region`、`Roi`、`Logic`、`Tuple`。分类、检测、分割的结果落在这些口上，见第 4 节。不增加「张量口」。张量留在算法 DLL 内部，出了 DLL 就是测值、矩形或区域。

`ToolIn` 已带 `solutionDir`、`toolDataDir`、`algLib`、`RunMode`。模型路径用得上。

### 2.2 算法是进程内一份原型

`AlgToolBaseRegistry::getPreferred` 返回登记时 `new` 出来的对象。`runAlgToolBase` 对这个对象调用：

```text
shot_init
execute
settle_result
```

没有按工具实例 `clone`。同一注册名、同一算法库的全部工具实例，跑的是同一个 C++ 对象。工站线程和调试试跑都可能进这个对象。

因此：

- 会话不能放在「每个流程工具一份」的成员里指望平台帮你建。平台没有这个调用。
- 会话不放在工具实例里。放在 `VisionOnnxCom.dll`。这个库必须是动态库。若做成静态库再链进三个算法 DLL，Windows 上每个 DLL 会有自己的一份静态状态，就会造出三个 `Ort::Env`。ONNX Runtime 要求进程里一个 Env。
- 缓存键是模型文件绝对路径加上修改时间。分类、检测、分割共用这一张表。
- `Session::Run` 可以多线程同时调用同一会话。缓存表的增删要加锁，`Run` 本身不加锁。
- 不在这一期改 `runAlgToolBase` 去按工具 `clone`。那会改变全部现有算法的对象身份。

`loadLearn` / `saveLearn` / `clearLearn` 目前没有任何业务代码调用。三个推理工具都在 `shot_init` 里读 `toolDataDir`，不新增一条平台生命周期。

### 2.3 失败怎么区分

`runAlgToolBase` 在原型不存在时：

| 字段 | 值 |
|---|---|
| `error` | true |
| `errCode` | `HS_ERR_NO_ALG` |
| `message` | 「未登记图像算法」 |
| 图像 | 透传输入 |

算法自己的 `fail` 把 `errCode` 设成非 0。`runAlgToolBase` 看到非 0 就把 `ToolOut.error` 设为 true。所以：

| 情况 | `error` | `ok` | 说明 |
|---|---|---|---|
| DLL 没加载 | true | false | 工具壳改写成「未登记推理算法」。公共字符串不动，二维工具仍显示「未登记图像算法」 |
| DLL 在，模型文件不在 | true | false | 「未加载模型」 |
| 模型输入形状对不上 | true | false | 带上实际输入名、类型、维度 |
| 最高分低于阈值，或个数、面积超出判断限 | false | false | NG。`errCode` 为 0 |
| 检测没有框、分割没有前景 | false | 由判断限决定 | 不是运行失败。默认判断限放得过，结果是 OK |

`settle_result` 的缺省实现只在说明为空时写成 OK 或 NG。三个算法都自己写说明，避免被盖成单个「NG」。没有目标时说明写「0 个目标」或「无前景」，`errCode` 仍为 0。

### 2.4 图像从哪来、画到哪

流程侧 `Job::inputIo` 按连线把图像放进 `ToolIn`。三个工具都调用 `runAlgToolBase(..., false)`，输出图沿用输入图，底图不换。分割出的区域叠在原图上，不把标签图当成新的底图。

设计态现在把 `Job::cachedOverlay` 里的 `HsObject` 经 `objectsToGraphics` 画成 `KindObject`。矩形和区域走得通。`HsObject` 没有文字种类，类别名进不了这条缓存。见第 3.3 节。

## 3. 平台改一次的部分

### 3.1 算法库

`AlgLibKind` 在 `AlgLibCv` 后追加 `AlgLibOnnx`。

| 项 | 值 |
|---|---|
| 登记名 | `onnx` |
| 界面短标题 | `Onnx` |
| 兼容解析 | `onnxruntime` 同样认成 `AlgLibOnnx` |

`algLibKindTitle`、`algLibKindRegName`、`algLibKindFromRegName` 一起补。不认识的登记名今天直接返回 false，插件若写错名字就进不了表。

工具参数里的算法库选项来自该 `toolName` 已登记的库。只有分类 DLL 时，下拉框里只有 Onnx。再放一个 Halcon 实现后，下拉框多一项，不用改界面代码。

### 3.2 工具大类

在 `ToolType` 末尾、`Max` 之前追加 `Infer`，界面名「深度学习」。与三维方案同一天落地时，`Calib` 后面先是 `Acquire3D`、`Prepare3D`、`Measure3D`、`Align3D`，`Infer` 接在这四类之后。

`defaultPortsForType(Infer)`：

| 方向 | 类型 | 给谁用 |
|---|---|---|
| 入 | `Image` | 全部推理工具 |
| 出 | `Logic` | 是否过阈值 |
| 出 | `Tuple` | 分数、类别、框的个数等 |
| 出 | `Region` | 分割 |
| 出 | `Roi` | 检测框 |

分类的 `ports()` 只声明入图像、出逻辑、出数值。区域和 ROI 留在大类的默认表里，检测和分割工具再声明。

| 函数 | 推理 |
|---|---|
| `toolTypeIsImageSource` | 否。三个工具都不换底图 |
| `toolTypeIsOverlaySource` | 是。文字、框、区域画在现有图像窗 |
| `toolTypeProducesOkNg` | 是 |
| `toolTypeDisplayAt` | 工具箱增加这一组。三个插件都在时，组里有三项 |
| `toolTypeTitle` | 「深度学习」 |

不增加端口类型，不改 `ToolIo` 的数组。`JobCfg` 按类型自动补的是图像、二维位姿和区域。`Infer` 不要算进图像来源，也不要因为它出了 `Region` 就被自动连到结果处理。框和区域只按用户拉的连线走。

### 3.3 图上的类别名

`ToolOut` 和 `AlgToolOut` 增加 `labels`，不进端口，不能连线。

```text
x, y     图像坐标，文字锚点。x 向右，y 向下
text     已经拼好的字符串，例如「划痕 0.91」
```

`runAlgToolBase` 把算法的 `labels` 抄到 `ToolOut`。`Job` 运行态在现有 `overlays`（`HsObject`）旁边按工具 id 再存一份 `labels`。设计态、调试态、运行格画完几何之后，对每个锚点追加一条 `GraphicKind::KindText`。

几何仍走原来的对象缓存。分类只有文字、没有框时，图像上仍能看到这一行字。检测的矩形、分割的区域不依赖这条文字也能画出来。

## 4. 三个工具的端口

| 任务 | 注册名 | 输入 | 输出 | 图像上 |
|---|---|---|---|---|
| 分类 | `infer.classify` | `Image` | `Tuple`：`classIndex`、`score`、`className`；`Logic` | 左上角一行字 |
| 目标检测 | `infer.detect` | `Image` | `Roi`：每个目标一个 `Rect1P`；`Tuple` 口 `classIndex`、`score` 与框下标对齐；汇总测值 `count`、`maxScore`；`Logic` | 框，框的左上角写类别和分数 |
| 语义分割 | `infer.segment` | `Image` | `Region`：每个前景类一块，行程编码；`Tuple` 口 `classIndex`、`area` 与区域下标对齐；汇总测值 `count`、`area`；`Logic` | 区域，区域外接框中心写类别和面积 |

框用 `Rect1P`，`Box2` 的 `x`、`y` 是左上角，`w`、`h` 是宽高，单位是原图像素，Y 向下。区域用 `HsRegion` 的行游程，行列也是原图。网络内部的缩放结果不送回流程。

下标对齐的规则：第 i 个框或区域，对应 `classIndex` 元组的第 i 个、`score` 或 `area` 元组的第 i 个。个数不一致是算法失败，不是 NG。

没有框、没有前景时，对应数组为空，`count` 为 0，`error` 为 false。OK 还是 NG 只看判断限。默认 `count` 的判断限是 0 到 100000，所以「一个目标都没有」默认是 OK。要检「必须有目标」时，把 `count` 的下限改成 1。要检「不能有缺陷」时，把 `count` 的上限改成 0。

## 5. 图像分类

### 5.1 工具壳

目录 `plugins\tools\Plugin.Tool.Infer.Classify`。链接 `VisionToolBase` 和 `VisionAlgToolBase`。不链接 ONNX Runtime，不链接 Qt。

| 项 | 值 |
|---|---|
| `toolName` | `infer.classify` |
| 显示名 | 图像分类 |
| 大类 | `Infer` |
| 版本 | `1.0.0.0` |
| `usesRoi` | false。整图进网络。要裁一块时，上游用现有预处理或 ROI 工具先裁成一张图再连进来 |

参数：

| 块 | 键 | 缺省 | 含义 |
|---|---|---|---|
| learn | `model` | `model.onnx` | 相对 `toolDataDir` 的文件名。界面选外部文件后拷进该目录，参数里只留文件名 |
| learn | `labels` | `labels.txt` | 同样相对 `toolDataDir`。一行一个类别，行号即类别下标。空行跳过 |
| run | `width` | 224 | 网络输入宽。小于 1 时算法失败 |
| run | `height` | 224 | 网络输入高 |
| run | `threshold` | 0.5 | 最高分低于该值则 NG |
| judge | `score` | 0 到 1 | 与测值 `score` 同名，参与总判定 |

`execute`：

1. `toolDataDir` 为空：`error = true`，说明「请先保存方案」。未保存时没有工具目录，权重没法落盘。
2. `model` 或 `labels` 拼出来的路径不存在：`error = true`，说明里带相对路径。这一步在进算法之前做，避免和「模型解析失败」混在一起。
3. `runAlgToolBase(toolName(), in, false)`。
4. 未登记时把说明改成「未登记推理算法」。
5. 用返回的 `className`、`score` 做一条 `labels`，锚点在图像左上角内缩 8 个像素。文字不写入 `HsObject`。
6. 输出图像保持输入图像。

模型字节不写进 `*.vpsol`。拷贝文件发生在参数编辑把外部路径写进工具目录的时候，由工具壳提供一个不依赖 Qt 的拷贝函数，界面只传源路径和 `toolDataDir`。调试宿主若还没有「选择文件并拷贝」的按钮，第一期允许用户把 `model.onnx` 和 `labels.txt` 直接放进工具目录，参数保持缺省文件名。专用按钮不属于算法，可以后补，不挡跑通。

`labels.txt` 使用 UTF-8。带 BOM 时去掉 BOM。类别名里的空格保留。

### 5.2 算法

目录 `plugins\algos\Plugin.Alg.Onnx.Infer.Classify`。`algLib()` 为 `AlgLibOnnx`。只链接 ONNX Runtime、`VisionAlgToolBase`、`HsCommData`。不链接 Qt，不链接 CUDA。

ONNX Runtime 使用 CPU 包，放在 `third_party\OnnxRuntime`。运行库随这个插件的输出目录拷贝，方式和 Halcon 运行库相同。仓库里不放 CUDA、cuDNN。

参数 `device` 这一期不出现在界面上。代码里若读到 `run` 的 `device` 且值不是 `cpu`，直接失败，说明「只支持 cpu」。避免静默改走 CPU，现场还以为在用显卡。

#### 会话

`Ort::Env` 和会话表在 `VisionOnnxCom.dll` 里，进程一份。分类算法只调用它，不自己再造一个 Env。

会话表：

| 项 | 约定 |
|---|---|
| 键 | 模型文件绝对路径，加上文件修改时间 |
| 值 | `Ort::Session` |
| 锁 | 只包住查找和插入 |
| 淘汰 | 表里超过 8 个条目时丢掉最早插入的。分类、检测、分割共用这张表 |
| 失败的路径 | 不缓存。下一拍还会再试，方便人替换文件后直接再跑 |

`shot_init` 里根据 `toolDataDir` 和 `learn.model` 取会话。`execute` 只做预处理和 `Run`。会话创建失败时 `shot_init` 返回错误，说明带上 ONNX Runtime 的异常原文，截断到 400 字。

`RunMode::Learn` 和 `Auto`、`Test` 对分类没有区别。分类没有「把当前图学进模板」。三种模式都只推理。不要在 Learn 里改写 `model.onnx`。

#### 预处理

全部在算法 DLL 内完成。不要求流程前面再挂一个专门给网络用的缩放工具。

1. 用 `HsImage::sampleRgb` 读像素。灰度图三个通道相同。Bayer 由 `sampleRgb` 现有逻辑解开。宽或高小于 1，或 `isNull`，失败，说明「没有图像」。
2. 缩放到 `width`×`height`。这一期用最近邻，实现短，不引入额外图像库。类别样例的验收图用已经接近目标尺寸的图片，避免最近邻成为结果争议点。换双线性时只改算法内部，端口和参数键不变。
3. 每个通道除以 255，得到 0 到 1。均值 0、标准差 1。模型若按 ImageNet 均值训练，这一期对不上，要在算法版本说明里写明。不把均值做成第一期参数，避免界面上一排数还没有对应的样例模型。
4. 排布 NCHW，batch 为 1，float32。颜色顺序 RGB。`HsImage` 若是 BGR，`sampleRgb` 已经按 R、G、B 给出，预处理不再看编码。

#### 网络输入输出

创建会话后读第一个输入：

| 检查 | 不满足时 |
|---|---|
| 元素类型是 float32 | 失败，写上实际类型 |
| 维度是 4 维 | 失败，写上实际维数 |
| batch 是 1 或动态维 | 其他固定 batch 失败 |
| 通道是 3 | 失败 |
| 高宽等于参数，或是动态维 | 固定高宽和参数不一致时失败，说明两边的数 |

输出取第一个张量。支持两种形状：

| 形状 | 解释 |
|---|---|
| `[1, C]` | C 类分数 |
| `[C]` | 同上 |

其他形状失败，写上实际维度。检测头和分割头由另外两个算法 DLL 解析，分类 DLL 不认。

分数的最大值若大于 1，或最小值小于 0，对这一向量做一次 softmax，再取最大下标。已经在 0 到 1 且总和接近 1 的向量不再做。两种都写入测值 `score`，并另写 `scoreRaw` 为 softmax 之前的最大分量，方便核对模型。

`classIndex` 为下标。`className` 从标签文件取。下标超出行数时名字用十进制下标，`ok` 仍按分数判断，说明里加上「标签不足」。

测值：

| 键 | 类型 | 含义 |
|---|---|---|
| `classIndex` | 整数，放在现有数值里 | 类别下标 |
| `score` | 浮点 | 用于判断的分数，softmax 之后若做过 |
| `scoreRaw` | 浮点 | 模型输出的最大分量 |
| `className` | 字符串 | 类别名 |

`className` 同时写入 `AlgToolOut.message`，形式为 `名称 0.97`。工具壳用同一句写 `labels`。逻辑口的 OK 由分数和 `threshold` 决定，再与名为 `score` 的判断限取与。任一不满足则 `ok = false`，`errCode = 0`。

### 5.3 和现有预处理工具的关系

平滑、增强、滤波已经是独立工具，输出图像。三个推理工具的输入都是一张 `Image`。需要裁切时，上游先裁成一张图再连进来。三个工具的 `usesRoi` 都是 false，不在原图上再画一块搜索区进网络。分类内部的缩放只服务网络张量，不把缩放后的图送回流程。

## 6. 目标检测

目录 `plugins\tools\Plugin.Tool.Infer.Detect` 和 `plugins\algos\Plugin.Alg.Onnx.Infer.Detect`。壳不链接 ONNX Runtime。算法链接 `VisionOnnxCom.dll`。

| 项 | 值 |
|---|---|
| `toolName` | `infer.detect` |
| 显示名 | 目标检测 |
| 大类 | `Infer` |
| 版本 | `1.0.0.0` |

端口：入 `Image`；出 `Roi`；出 `Tuple` 口名 `classIndex`；出 `Tuple` 口名 `score`；出 `Logic`。

| 块 | 键 | 缺省 | 含义 |
|---|---|---|---|
| learn | `model` | `model.onnx` | 相对 `toolDataDir` |
| learn | `labels` | `labels.txt` | 一行一个类别，行号即类别下标。检测没有隐含的背景类 |
| run | `width` / `height` | 640 | 网络输入边长 |
| run | `threshold` | 0.25 | 低于该分数的框在 NMS 前丢掉 |
| run | `iou` | 0.45 | 同一类别内的 NMS 交并比。小于 0 当作 0，大于 1 当作 1 |
| run | `maxCount` | 100 | NMS 之后最多留下几个框。小于 1 时失败 |
| judge | `count` | 0 到 100000 | 框的个数 |
| judge | `maxScore` | 0 到 1 | 留下的框里的最高分 |

`execute` 的文件检查、未保存方案、未登记说明与分类相同。未登记时说明仍是「未登记推理算法」。算法返回后，壳为每个框写一条 `labels`，锚点是矩形左上角，文字是 `类别 分数`。

### 6.1 预处理和坐标换回

检测用 letterbox，不把图像拉变形。`VisionOnnxCom` 提供这一步，分割共用。

1. `scale = min(网络宽 / 图宽, 网络高 / 图高)`。
2. 图按 `scale` 缩放，最近邻。放进网络画布的左上为零、居中：左右边距 `padX = (网络宽 - 缩放后宽) / 2`，上下同理。空白填 114。
3. 再按分类的方式做成 NCHW、RGB、除以 255。
4. 网络输出的框若在网络画布坐标里，先减去 `padX`、`padY`，再除以 `scale`，得到原图像素。落到图像外的部分裁掉。宽或高小于 1 的框丢掉。

分类继续用拉伸到 `width`×`height`，不走 letterbox。分类没有要映射回原图的框。

### 6.2 网络输出

输入检查与分类相同：float32、四维、batch 为 1 或动态、通道 3、高宽与参数一致或为动态维。

输出认两种常见检测头。坐标都是网络画布上的中心点加宽高，像素，还没换成原图。

| 形状 | 每一列或每一行 |
|---|---|
| `[1, N, 5+C]` | `cx cy w h`、目标置信度、C 个类别分。得分是目标置信度乘类别分。类别取类别分最大的下标 |
| `[1, 4+C, N]` 或 `[1, N, 4+C]` | `cx cy w h` 加 C 个类别分，没有单独的目标置信度。得分是最大类别分 |

N 小于 1，或 C 小于 1，失败。两种形状对不上时失败，说明里写实际维度，不按分类向量去解读。

然后：

1. 丢掉得分低于 `threshold` 的框。
2. 按类别分开做贪心 NMS。两框交并比大于 `iou` 时留下得分高的。
3. 全部类别合在一起按得分从高到低截到 `maxCount`。
4. 换回原图坐标，写成 `Rect1P`。`classIndex` 与 `score` 两个元组跟框的顺序一致。
5. `count` 为留下的框数。`maxScore` 为这些框的最高分；没有框时为 0。
6. `ok` 与 `count`、`maxScore` 的判断限取与。没有框且判断限允许 0，则 `ok` 为 true，`errCode` 为 0。

标签行数少于某个类别下标时，该框仍保留，名字用十进制下标，说明里加上「标签不足」。

## 7. 语义分割

目录 `plugins\tools\Plugin.Tool.Infer.Segment` 和 `plugins\algos\Plugin.Alg.Onnx.Infer.Segment`。链接方式和检测相同。

| 项 | 值 |
|---|---|
| `toolName` | `infer.segment` |
| 显示名 | 语义分割 |
| 大类 | `Infer` |
| 版本 | `1.0.0.0` |

端口：入 `Image`；出 `Region`；出 `Tuple` 口名 `classIndex`；出 `Tuple` 口名 `area`；出 `Logic`。不出图像。标签图不作为底图，也不作为输出口。

| 块 | 键 | 缺省 | 含义 |
|---|---|---|---|
| learn | `model` | `model.onnx` | 相对 `toolDataDir` |
| learn | `labels` | `labels.txt` | 行号即类别。第 0 行一般是背景 |
| run | `width` / `height` | 512 | 网络输入边长 |
| run | `background` | 0 | 这个类别不生成区域 |
| run | `minArea` | 16 | 前景像素少于该值的类丢掉。小于 0 当作 0 |
| judge | `count` | 0 到 100000 | 留下的前景类个数 |
| judge | `area` | 0 到 1e12 | 留下的前景像素总数 |

预处理与检测相同，用 letterbox。网络输出的标签在网络画布上。先裁掉 `padX`、`padY` 外的填充，再用最近邻缩回原图宽高。最近邻是为了不把类别编号插成小数。缩回之后再数面积、再编游程。

输出认两种：

| 形状 | 解释 |
|---|---|
| `[1, C, H, W]` float | 每个像素取 C 个通道里最大的下标，得到类别图 |
| `[1, H, W]` 或 `[1, 1, H, W]` 整数 | 已经是类别图 |

H、W 必须等于网络输入高宽，或等于去掉 letterbox 填充之后的高宽。对不上则失败，并写上实际维度。不要把 `[1, C]` 的分类向量当成分割。

每个不是 `background`、且像素数不小于 `minArea` 的类别，编成一块 `HsRegion`：按行扫描，连续前景压成一条 `Chord`（闭区间）。区域下标从 0 连续编号，类别下标小的在前。`classIndex`、`area` 元组与这个顺序对齐。

`count` 是区域块数。`area` 是这些块的像素和。`labels` 的锚点用该区域外接框中心，文字是 `类别 面积`。没有前景时数组为空，说明「无前景」，是否 OK 只看 `count` 和 `area` 的判断限。

一块区域是一整类，不是一个个实例。同一类里分开的两团像素仍在同一块区域里。要每个目标一块掩膜，那是实例分割，不放进这个工具。

## 8. 界面

三个工具都没有新窗口。

| 位置 | 行为 |
|---|---|
| 工具箱 | 「深度学习」下有图像分类、目标检测、语义分割。缺哪个 DLL，就少哪一项 |
| 参数页 | 现有由 `paramFields` 生成的表 |
| 图像窗 | 底图始终是输入图。分类只有文字。检测画矩形和文字。分割画区域和文字 |
| 结果表 | 分类看 `className`、`score`。检测看 `count`、`maxScore`。分割看 `count`、`area` |
| 算法库列 | 有 DLL 时显示 Onnx |

调试宿主与 Blob 同一条路径：输出图交给 `HsImageWindow`，矩形和区域从 `objects` 来，文字从 `labels` 来。不经过点云页。

运行九宫格仍是图像格。推理工具绑到某一格时，这一格显示输入图加框或区域，不因为大类换成别的控件。

## 9. 线程和耗时

`execute` 在现有工站线程或调试线程池里同步跑完再返回。不在算法 DLL 里再开推理线程，也不向 UI 线程抛进度。

第一期不设超时。检测和分割比分类重，仍在这一拍里算完再返回。若以后要超时，在工具 `run` 参数加 `timeoutMs`，由壳在调用前后计时。

同一会话的并发 `Run` 允许发生。预处理、NMS、游程编码用各自栈上的缓冲，不写进原型成员。

## 11. 验收

1. 工具箱「深度学习」下有图像分类、目标检测、语义分割。去掉其中一个算法 DLL，只有那一项执行失败，说明是「未登记推理算法」。删掉 `model.onnx` 时说明是「未加载模型」。找圆工具的未登记说明不变。
2. 分类：输入 `[1,3,224,224]`、输出 `[1,C]` 的模型能跑。图像窗仍是原图尺寸，左上角有类别和分数。分数低于 `threshold` 时逻辑为 NG，`error` 为 false。
3. 把检测模型交给分类工具，分类失败，说明里有实际维度，图上不出现框。把分类模型交给检测或分割，同样失败，不画出乱框或整幅区域。
4. 检测：一张图里两个同类目标，NMS 之后是两个 `Rect1P`，坐标落在原图内，`classIndex` 与 `score` 的个数和框数相同。把 `iou` 调到 0 且两框重叠时，只留分高的一个。`count` 下限设为 1 且图中无目标时，逻辑为 NG，`error` 为 false。
5. 分割：输出 `[1,C,H,W]` 的模型能跑。背景类没有区域。两个前景类得到两块 `HsRegion`，`area` 元组与区域一一对应，区域叠在原图上，底图尺寸不变。`minArea` 大于某一类的像素数时，该类消失，`count` 减一。
6. 两个检测工具指向不同的 `toolDataDir`，框各自对应自己的模型。会话表不串文件。
7. 未保存方案时三个工具都要求先保存。onnx 不写进 `*.vpsol`。
8. 旧方案没有推理工具时，图像窗行为不变。三个 DLL 都没加载时，工具箱不出现这三项。

## 12. 明确不做

训练、数据集标注、模型剪枝、TensorRT、CUDA、一次喂多张图、异常检测热力图、实例分割、在这三个工具里画搜索区。

实例分割是每个目标一块掩膜，输出同时有框和区域。那要单独的 `infer.instance`，不改 `infer.segment` 的注册名，也不把实例掩膜塞进「一类一块」的区域口。旋转框不在 `infer.detect` 里。这一期的框只有 `Rect1P`。
