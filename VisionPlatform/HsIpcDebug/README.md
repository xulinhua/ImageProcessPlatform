# HsIpc 调试器

本机进程通讯的收发窗口。链接 `HsIpc.dll`，不改库，也不进入 `VisionApp`。用来确认视觉和运控是不是开在同一条通道上。

界面样式在本工程的 `debug_theme.h`，不和设备通讯调试器共用。程序图标是 Lucide 的 workflow（ISC），两个方块连在一起，表示两个进程。

## 编译

在 `VisionPlatform.sln` 的 **ClassLib / Port** 里生成 `HsIpcDebug`。配置 **Debug|x64** 或 **Release|x64**。产出 `bin/<平台>/<配置>/HsIpcDebug.exe`，和 `HsIpc.dll` 在同一目录。需要本机 Qt 5.15.2，环境变量 `QTDIR` 指向对应套件。

## 使用

1. 两边选同一种传输、同一个通道名。谁先点打开谁创建对象。
2. 共享内存再填信号环容量和图像槽。套接字再填主机和端口，主机空则是 `127.0.0.1`。管道和消息队列只要通道名。
3. 打开之后参数锁住。选消息类型，填字段，点发送。通道开着时工作线程一直 `poll`，收到的行出现在下方表格。
4. 点图像那一行，右侧预览 JPEG。其它格式只显示字节数。
5. 勾选定时心跳后按间隔发心跳。状态行用 `hs_ipc_last_recv_ms` 显示多久没收到。
6. 保存记录写成 UTF-8 文本。再开一个会另起进程，通道名相同即可对打，谁先打开谁创建。
7. 管道、消息队列和套接字上，图像或文件超过 1MB 时，发送摘要写明拆成几片，接收摘要带分片序号。
8. 关闭窗口时关闭通道。

返回码按库的约定显示：成功、超时、参数错、满、IO、协议、过大。

`poll` 填出的指针在下一次 `poll` 之前就失效，所以工作线程先把名称、文本和像素拷进 `LogRow`，再交给界面。
