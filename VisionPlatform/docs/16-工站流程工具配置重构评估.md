## 3. 当前主要痛点

1. **Job `links[]` `root` 双真*：画布拖线、自动串行重建、树结构调整可能互相覆盖；调试「谁为准」成本高2. **`ToolConfig` 语义过载**：身份、参数、ROI、画布坐标、运行态字段同 struct；UI / 序列/ draft 对比都要特殊分支（如 enhance/smooth pipeline）3. **连线查询路径Job**：`ToolIoPanel`、`findLinkToPort` 等必须持`JobConfig*`，无法只凭工具实例完成「我的输入从哪来」?4. **「IO」边界模*：持ROI vs 运行结果叠加 vs 调试变量（`runtime` 键）分散在三处（`ToolConfig`、`JobRuntime`、`ToolOut`）5. **命名**：「ToolBase」在沟通中既指插件又指实例聚合，易与提3 混淆6. **Alg 层演进中**：插件化`AlgorToolBase` 已瘦身为 `(toolName, algLib) + run()`；与旧文`08` 中「VisionAlgoBase 大包」叙述部分过时，需单独定稿（见 §7）

## 5. 推荐数据形态（实例侧）

建议在现`ToolConfig` 内拆出嵌套四块语义（Info/Link/Para），运行门面 `Tool` **Info/Link/Para/IO 四者平**不另ToolRecord 包装*；序列化仍可 flatten 到现JSON 键以兼容
### 5.1 `ToolInfo`（持久）

**只含身份**（产品口径与方案 26 一致；`algLib` / `deviceId` 归入 Para）：

```text
id, toolName, type, name, enabled
```

- 对应现有身份字段；`type` 仍以注册`ToolBase::type()` 为准做校验（`toolFromJson` 一致）- **不含**画布坐标（已定：流程布局表）
### 5.1b 流程布局（已定：单独布局表）

产品口径（方26）：**单独做流程布局*；工具不保存坐标/折线。ToolInfo 不含 canvas 字段
### 5.2 `ToolLink`（持久，归属工具
**推荐规则**：每条有向边描述「本工具某输入端?上游工具某输出端口」?
```text
struct ToolInputLink {
  PortSlot toPort;           // 本工具输入槽
  ObjectId fromToolId;
  PortSlot fromPort;
  // 不含 route/拐点 ??Job 布局};
```

- 工具侧：`std::vector<ToolInputLink> inputs;`（或 `incoming`）- **多输/ 多类型端*：一端口至多一条主连线（与`connectToolPorts` 替换语义一致）；若未来要多路合并，再扩`vector` 或显merge 工具- **Job `links[]`**：Phase 2 起可作为 **派生缓存**（保存时 `links = flatten(tools[*].inputs)`），加载时若仅存Job.links **回填** 到各工具
**查询 API**：`Job` 调度时优先读工具`inputs`；`job.findLinkToPort(toId, port)` 改为扫描 tools 或读缓存
### 5.3 `ToolPara`（持久）

```text
ParamMap params;   // 配方/算法/UI 调试参数
QString algLib;   // 算法后端，可?参数而非身份
ObjectId deviceId; // 采集绑定设备，可?参数而非身份
RoiList rois;      // 界面绘制ROI ?参数；不ToolIO
// pipeline 等仍可通过 params 或子对象 enhanceSteps 表达
```

- 运行态键 **禁止** 进入 `ToolPara`（延`migrateToolRuntime` / `isRuntimeParamKey`）- `ToolRecipe` 对齐：draft ?diff `ToolPara`（含 algLib / deviceId / rois）
### 5.4 `ToolIO`（仅运行态，不持久化
本拍综合后的运行数据（对齐现`ToolIo` / `ToolOut`，不另起第三套）
| 内容 | 持久化|
| --- | --- |
| 输入/输出图、结果图、区域、轮廓、位姿、逻辑量、debug、叠| ***；留`ToolRuntime` / `JobRuntime` |

- **界面 ROI 不进 ToolIO**（已Para）- 不写`*.vpsol`；若需「上次调试截图」走 `vpdata` 或显式导出- 画布坐标**Job 流程布局**不属** ToolInfo / ToolIO / ToolLink? 
- ToolLink **只存两端**（fromTool/fromPort ?toPort）；折线路由进布局表
### 5.5 插件 `ToolBase` / `AlgorToolBase`（保持现状职责）

- **`ToolBase`**：类型元数据 + `execute(ToolIn)->ToolOut`?- **`AlgorToolBase`**：仅 `run(AlgorToolIn)->AlgorToolOut`?- 实例四块 **不进* 上述插件基类

## 6. 连线归属规则（推荐）

1. **权威存储（目标态）***输入边挂在消费方工具**（下游工具的 `inputs[]`）。理由：`ToolIn` / `ToolIoPanel`「为本端口选上游」交互一致；删除工具时清理其 `inputs` 及全 Job 内指向它的边即可2. **Job 仍保*?   - `root` **执行*（并If/顺序）—*不可替代**?   - `resultRules`、`trigger` 等流程级策略   - 可**`links[]` 冗余字段**（兼容旧文件、画布全局遍历加速），保存时tools 生成，加载时tools 为准若两者冲突则定义优先级（建议 **tool.inputs 优先**）3. **树与线关*?   - 纯串行链：可继续提供「按树重建默image 连线」的**辅助命令**（现 `rebuildSerialLinks`），但用户手改连线后不得 silently 覆盖（需 UX 确认或仅改「未自定义」边）4. **?Job**：不允许；连线引用限定同一 `JobConfig.tools` ?id?5. **校验**：保加载时验`fromToolId`/`toToolId` 存在、端口类型匹`PortDesc`（可复用 `ToolRegistry` 端口表）
