# 工具插件方案

约束：VS2015、C++11、Windows。平台只改一次。之后新增一种工具，只往插件目录丢 DLL，不改 `VisionCore`、`VisionUi`、`VisionToolUi`。算法 DLL 不使用 Qt。`VisionCore` 改为 DLL。工具基类、算法基类和具体工具 DLL 都不引用它。

## 1. 结论

一个工具一个 DLL，一种算法库上的一个实现再各一个 DLL。两边用同一个 `toolName` 接上。判定、通信、采集和图像工具全部这样拆，不再留 `VisionTools.Base.dll` 这种大包。

`VisionCore` 改为 DLL，只放方案、工站、流程和调度。它引用工具基类和算法基类，反向不许。工具基类和注册表进 `VisionToolBase.dll`，算法基类、算法注册表、`runAlgorToolBase` 进 `VisionAlgorBase.dll`。具体工具 DLL 只链接自己的基类 DLL，不链接 `VisionCore.dll`。注册表因此全进程只有一份。

没有对应算法 DLL 时，不登记空的 Builtin 占位。工具壳的 `execute` 直接返回，界面显示未登记算法。要看出效果的样例必须带 Halcon 实现，找圆就按这个拆。

参数页全部由工具壳的参数说明生成。现有按工具名写的专用页删掉，不保留两套。

## 2. 现在缺什么

已经有的：

- 工具库列表来自 `ToolRegistry::all()`，不是写死的菜单。
- 算法按 `(toolName, algLib)` 登记。`algLib` 是算法库，取值就是库名，例如 `halcon`。加载器已经扫描 `plugins\tools\*.dll` 和 `plugins\algos\*.dll`。
- 插件通过 `IPluginHost::addTool` / `addAlgor` 登记。同名先登记的留下。

对不上的是交付单位。找圆、找线、Blob、判定、通信、采集的壳都在 `VisionTools.Base.dll` 的 `registerTools()` 里。Halcon 实现都在 `VisionAlgo.Halcon.dll` 里。Builtin 是整包占位，没有对应算法时也占着一个算法库。

参数页在 `registerToolEditors()` 里按名字登记。`ImageAlgoTool::capabilities()` 按名字写死 ROI。

`VisionTools.Base.dll` 和 `VisionAlgo.Halcon.dll` 都静态链接 `VisionCore.lib`。注册表单例因此各有一份。`host->addAlgor` 写进主程序那一份，工具壳若在自己的 DLL 里再查，查到的是空的。`ToolBase` 现在还直接包含方案头文件。拆开之后，工具和算法不能再引用 `VisionCore`：它们只用自己的基类 DLL，加上 `VisionCommon` 和图像数据。方案、工站、流程留在 `VisionCore.dll`，由它去调用工具。

## 3. 市面怎么做

对照的是视觉软件加工具的方式，不是某一个 SDK 的类名。

**海康 VisionMaster 一类国产软件。** 安装目录下放一个工具模块，工具库里就出现。参数页由工具自带的参数描述生成。没有算法模块时，工具还在，运行直接告诉你没有实现，不放一个空算法占位。

**康耐视 VisionPro。** 新工具以 DLL 附加，平台按接口发现，不在主程序里列出全部工具名。工具类继承平台给出的基类，基类在公共程序集里，不跟每一个工具再拷一份。

**HALCON。** 外部过程按目录装入，不重新编译 HALCON。本平台用 DLL，边界相同：目录即插件，主程序不点名。

## 4. 目标结构

```text
VisionPlatform.exe
        |
        v
VisionCore.dll                 方案、工站、流程、调度
        |  只这一方向引用
        +-- VisionToolBase.dll
        |         ToolBase、ToolRegistry
        |         参数说明、ToolCaps；不包含 VisionCore
        |
        +-- VisionAlgorBase.dll
                  AlgorToolBase、AlgorToolBaseRegistry、runAlgorToolBase
                  不包含 VisionCore

plugins\tools\                 只链接 VisionToolBase.dll
        Tool.Locate.FindCircle.dll
        Tool.Logic.Judge.dll          execute 自己返回，无算法 DLL
        Tool.Camera.File.dll

plugins\algos\                 只链接 VisionAlgorBase.dll
        Algo.Halcon.FindCircle.dll    algLib = halcon
                                      没有实现就不放文件
```

`VisionTools.Base.dll`、`VisionAlgo.Halcon.dll`、`VisionAlgo.Builtin.dll`、`VisionAlgo.OpenCV.dll` 在工具拆完后删除。OpenCV 以后真有某个工具的实现时，再单独丢一个算法 DLL，不留空包。

工具 DLL 只做这些事：继承 `ToolBase`，填 `toolName`、显示名、缺省参数、参数说明、`ToolCaps`、端口，交给 `host->addTool`。需要算法的，`execute` 调用 `VisionAlgorBase.dll` 里的 `runAlgorToolBase`。不需要算法的（判定、通信、采集），`execute` 在工具 DLL 里直接返回，不登记假算法。

算法 DLL 只继承 `AlgorToolBase`，实现 `toolName()`、`algLib()`、`run()`，交给 `host->addAlgor`。不带 Qt，不创建工具壳。

没有登记到的算法时，`runAlgorToolBase` 不造 Builtin 对象。工具接口返回失败，说明写「未登记图像算法」。界面就显示这句，不出现空的算法库选项。

## 5. 工具与算法之间的数据

三层，只向下传。算法看不见方案，工具看不见工站调度。

```text
VisionCore          连线、调度、存盘
    |  ToolIn / ToolOut
    v
VisionToolBase      工具与工具之间
    |  AlgorToolIn / AlgorToolOut     只有图像类工具才走
    v
VisionAlgorBase     一次像素计算
```

**方案层留在 `VisionCore`。** `Solution`、工站、流程、`ToolConfig`、连线、按工具 id 缓存的结果。这些类型不出现在工具 DLL 和算法 DLL 的头文件里。调度在调用前把配置拆开，调用后把结果写回缓存。

**工具层在 `VisionToolBase`。** 流程里工具和工具之间传 `ToolIo`，一类一个数组：

| 字段 | 内容 |
|---|---|
| images | `HsImage` |
| regions | `HsObject`（区域） |
| contours | `HsObject`（轮廓） |
| rois | `ToolRoi`：几何是 `HsObject`，旁边一个查找条数 |
| poses | `ToolPose` |
| logics | 是否 OK，以及说明 |

`execute` 的入参改成 `ToolIn`，出参仍是 `ToolOut`。不再传入带 `Solution*`、`JobConfig*`、`ToolConfig*` 的 `ToolContext`。

`ToolIn` 只有这些：

| 字段 | 谁填 | 说明 |
|---|---|---|
| input | 平台 | 首张输入图，与 `inputIo.images` 一致，方便直接用 |
| inputIo | 平台 | 按连线收好的上游 `ToolIo` |
| params | 平台 | 本工具参数，已用壳上的缺省值补齐 |
| solutionDir | 平台 | 方案所在目录，未保存则为空 |
| toolDataDir | 平台 | 本工具数据目录，未保存则为空 |

`ToolOut` 只有这些：`ok`、`message`、`elapsedMs`、首张 `image`、`objects`（`HsObject`）、`values`（`ParamMap`）、分类后的 `io`。平台用 `io` 给下游连线，用 `image` 显示。`objects` 只在交给图像窗时转成 `Graphic`。

判定、通信、采集只使用 `ToolIn` / `ToolOut`。它们不构造 `AlgorToolIn`。

**算法层在 `VisionAlgorBase`。** `run` 的入参、出参不含端口、不含 `ToolIo`、不含方案。由工具壳转换，不由流程直接调用。

`AlgorToolIn`：

| 字段 | 来源 |
|---|---|
| image | `ToolIn.input`，可空 |
| rois | 本工具自己的 `ToolRoi`，加上 `inputIo.rois` |
| poses | `inputIo.poses` |
| regions | `inputIo.regions`，本身就是 `HsObject` |
| contours | `inputIo.contours`，本身就是 `HsObject` |
| params | `ToolIn.params` |
| solutionDir、toolDataDir | 原样抄入 |

位姿作用到 ROI 上，在 `runAlgorToolBase` 里做，算法 `run` 拿到的 `rois` 已是跟随之后的。算法不自己改连线。算法入参没有 `Graphic`，绘制只留在工具层和界面。

`AlgorToolOut`：`ok`、`message`、`image`（空则沿用输入）、`objects`（`HsObject`）、`values`。工具壳把它写成 `ToolOut`：`values` 照抄，`ok` 写入 `io.logics`。`objects` 按种类拆开：区域进 `io.regions`，轮廓进 `io.contours`，圆、矩形、直线拆成 `ToolRoi`（`searchCount` 为 0）放进 `io.rois`。算法层和工具层都不传 `Graphic`。`Graphic` 只在画到 `HsImageWindow` 之前由 `objectsToGraphics` 生成。

**两边都能用、但不属于任何一层业务的类型**放在 `VisionCommon` 和 `HsCommData`，只有头文件和数据结构，没有注册表单例：

| 类型 | 位置 | 谁用 |
|---|---|---|
| `HsImage`、`HsRegion`、`HsContour`、`Graphic`、`HsObject` | `HsCommData` | 工具层、算法层 |
| `ParamMap` | `VisionCommon` | 参数和数值结果 |
| `ToolRoi`、`ToolPose` | 从 `VisionCore` 挪到 `VisionCommon` | 工具层传 ROI 和位姿，算法层只读 |

`ToolRoi` 不再自己存中心、长短轴、转角、顶点和游程。几何用已经封装的 `HsObject`：

| 字段 | 内容 |
|---|---|
| geom | 一个搜索区。`count()` 为 1，种类是圆、椭圆、轴对齐矩形、旋转矩形、直线、折线、轮廓或区域 |
| searchCount | 这一块里查找几条。0 表示用工具参数里的缺省条数 |

算法按 `geom.kind()` 取 `circleAt(0)`、`rect2At(0)`、`regionAt(0)` 等，不再认 `RoiKind`，也不再定义第二套圆和矩形。`RoiKind` 删除。

拷贝 `ToolRoi` 时 `geom` 只共享句柄。算法要改几何，先 `clone()`。

箭头、十字、点、文字不是搜索区。它们在 `Graphic` 的 `GraphicKind` 里，用来显示，不进 `AlgorToolIn.rois`。画布上可拖的 ROI 是 `Graphic`，`role` 为绘制，`geom` 就是这块 `ToolRoi.geom`。

`ToolConfig` 只留 `rois`，不再单独存一份 `roi`。存盘按 `ObjectKind` 写具体形状。读旧方案时，把原来的 `x / y / a / b / phi / 顶点 / 游程` 转成对应的 `HsObject`；箭头、十字、点、文字转成 `Graphic`，不进 `rois`。写出时只写新结构。

参数说明（标题、类型、范围、选项）只在工具壳上，给界面生成表单。不放进 `AlgorToolIn`。算法只读 `params` 里的键。

## 6. 对接约定

`toolName` 仍是小写点分，例如 `locate.find_circle`。壳和算法必须逐字相同。

`algLib` 只给真正有 DLL 的算法库，现在就是 `halcon`。方案里为空时，用已登记的算法库；一个都没有就直接返回。优先序里去掉 `builtin`。以后增加 OpenCV，只把该工具的算法 DLL 放进 `plugins\algos`，并在优先序里加上 `opencv`。这是平台的一次改动，不属于单个工具。

端口默认跟工具大类走。不够用时由该工具 DLL 覆盖 `ports()`。

同名工具壳不要放两个。同一 `toolName` 的两个算法 DLL，`algLib` 不同则共存，相同则先登记的留下。

接口版本仍是 1，不新增导出函数。

依赖只允许向下：`VisionCore.dll` 链接两个基类 DLL；工具 DLL 只链接 `VisionToolBase.dll`；算法 DLL 只链接 `VisionAlgorBase.dll`。两边都不链接 `VisionCore.dll`。算法 DLL 不调用 `Translate`，错误说明用中文键交给平台翻。

## 7. 参数页和 ROI

工具壳提供参数说明，不提供 Qt 控件。`VisionToolUi` 只根据说明生成表单。`registerToolEditors()` 和现有专用页（找圆、Blob、增强、相机、判定、通信等）删掉。

每项至少包含：

| 字段 | 作用 |
|---|---|
| key | 写入 `ParamMap` 的键，与算法 `run()` 读取的键相同 |
| 标题 | 界面文字，作翻译键 |
| 类型 | 布尔、整数、浮点、字符串、路径、设备 |
| 默认值 | 新拖进流程时的初值 |
| 范围 | 整数和浮点的最小、最大；没有则不限制 |
| 选项 | 字符串枚举；空表示自由文本 |

路径和设备是为了采集工具也能用生成页，不必再留专用界面。布尔用勾选，数值用数值框，有选项的字符串用下拉，路径用文本加选择按钮，设备用当前方案里的设备列表。分组、表格型参数本期不做。

ROI 由壳写进 `ToolCaps`：是否允许画、是否多 ROI、推荐种类。推荐种类用 `ObjectKind`，不再用 `RoiKind`。`toolCaps(toolName)` 问注册表里的壳。平台代码里不再出现某个工具的名字。

算法 `run()` 只读 `ParamMap` 和 ROI，不读参数说明。

## 8. 本期明确不做

- 工具 DLL、算法 DLL 引用 `VisionCore`。
- 保留 Builtin 或任何空算法占位。
- 保留旧的专用参数页。
- 算法 DLL 带 Qt，或自己注册参数页工厂。
- 插件热插拔。加载后仍不 `FreeLibrary`。
- 改 `toolName` 规则，或做旧名迁移。`canonicalizeToolName` 保持不动。
- 再保留 `RoiKind`，以及 `ToolRoi` 上的 `x / y / a / b / phi`。旧方案只在读入时转一次。
- 参数分组、表格型参数。

## 9. 落地顺序

1. `VisionCore` 改为 DLL。同时抽出 `VisionToolBase.dll` 和 `VisionAlgorBase.dll`。`ToolRoi` 改为 `HsObject` 加 `searchCount`，`ToolPose` 一起挪到 `VisionCommon`。`backendId` 改名为 `algLib`。`execute` 改为 `ToolIn` / `ToolOut`，去掉对方案、工站、流程指针的依赖。现有大包改为只链接基类 DLL，找圆仍能跑，用来确认单例只有一份，且插件工程里看不到 `VisionCore`。
2. 工具壳增加参数说明和 `ToolCaps`。删掉专用参数页，全部改为按说明生成。没有算法时 `execute` 直接返回「未登记图像算法」。优先序去掉 `builtin`。
3. 先拆找圆：`plugins\tools` 一个壳，`plugins\algos` 一个 Halcon 实现。工具库里看得到，参数能改，Halcon 能出圆。没有 Halcon DLL 时运行直接提示没有算法。
4. 其余工具按同样方式拆完，包括判定、通信、采集、找线、Blob。拆完删除 `VisionTools.Base.dll`、`VisionAlgo.Halcon.dll`、`VisionAlgo.Builtin.dll`。没有实现的 OpenCV 大包一并删除。
5. 把目录和 `toolName` 约定写进 `architecture.md`。

第 3 步做完，找圆已经是「不改平台就能换 DLL」。第 4 步做完，现有工具全部按这个单位交付。

## 10. 已定

1. 一个工具壳一个 DLL，每种算法库的实现再各一个 DLL。
2. 参数页由工具壳的参数说明生成。算法 DLL 不带 Qt。旧的专用参数页删除，按本方案重写。
3. `VisionCore` 改为 DLL。工具基类一个 DLL，算法基类一个 DLL，具体工具继承对应基类。工具和算法不引用 `VisionCore`。
4. 所有工具都拆，包括判定、通信、采集。
5. 样例用找圆加 Halcon。不保留 Builtin 空占位；没有算法 DLL 时工具接口直接返回，界面显示没有算法。
6. `ToolRoi` 的几何用 `HsObject`。旁边只留 `searchCount`。`RoiKind` 和原来的中心、长短轴、转角、顶点、游程不再作为接口字段。
7. 算法库字段叫 `algLib`，不再叫 `backendId`。取值仍是库名，例如 `halcon`。
